## 1. Summary & non-goals

A new **Single Strategy** tab with a single-select strategy picker and one
**shared benchmark selector**, organized into three sections:

1. **Profile + cumulative chart** (two columns).
2. **Tabbed monthly-return calendar table** (absolute / outperformance /
   vol-adjusted).
3. **Tabbed analytics charts** (weekly-vs-benchmark scatter, histogram vs
   benchmark, monthly factor scatter).

**Non-goals (hard constraints):**

- **Platform and Multi-Strategy Analysis tabs are unchanged.**
- **No extra BQL call** — benchmarks already ride the single fetch; every view
  computes from the cached `universe_prices` / `arp_universe_prices`.
- **No new runtime deps;** render via v0.6.0 HTML templates; colors/sizes from
  `style.py` tokens.

## 2. Motivation

The dashboard has whole-catalog (Platform) and multi-strategy comparison
views, but **no single-strategy deep-dive**. Clients want one place to see a
strategy's profile, its monthly return calendar, and its behavior versus a
benchmark and the macro premia.

## 5. Workstream B — New stats (`src/stats/` package)

> `stats` is now the **`src/stats/` package** (`_common` / `performance` /
> `risk` / `rolling` / `regime` / `factors`), re-exported from
> `src/stats/__init__.py`. Add the new helpers in a focused submodule (e.g.
> `src/stats/calendar.py`) and re-export them; `ann_sharpe` lives at
> `src/stats/performance.py:258`.

- `monthly_returns(prices)` — resample to month-end, compound daily returns.
- `weekly_returns(prices)` — resample to weekly.
- `monthly_realized_vol(returns)` — within-month daily-return std (vol-adjusted
  tab).
- `calendar_return_table(prices, *, kind, benchmark=None)` — a year×month
  matrix for `kind` ∈ {`absolute`, `outperformance` (strategy − benchmark
  monthly), `vol_adjusted` (monthly ÷ monthly realized vol)}, plus per-year
  **Return** and **Sharpe** (reuse `ann_sharpe` on each calendar year's daily
  slice).
- `ols_fit(x, y)` — slope / intercept / R² for the weekly-scatter regression
  line.
- `monthly_factor_correlations(prices, factor_returns, *, window)` — the
  strategy's per-month correlation to a factor (reuse `rolling_correlation`);
  consumes v0.7.0 `equity_risk_premium` / `term_premium`.

All new helpers get `pytest` unit tests (degenerate cases included).

## 6. Workstream C — Tab shell + Section 1 (profile + chart)

Add the **Single Strategy** tab (extend `_activate_tab` to a 3-way swap), a
single-select strategy `Dropdown`, and the shared benchmark selector. Section 1
is two columns:

- **Left — metadata card:** name, ticker, currency, return type, theme,
  category, **description** (templated; NA-safe).
- **Right:** a prominent cumulative line chart (reuse `_update_line`) + a
  compact standard-performance table (`perf_table` + `since_inception_perf`) +
  the option to **overlay one or more core benchmarks** (extra `cum_perf`
  traces driven by the shared benchmark selector).

## 7. Workstream D — Section 2 (calendar table)

A 3-tab control (Tab/pill) swapping one DataGrid between **Absolute** /
**Outperformance** / **Vol-adjusted**, each from `calendar_return_table(...)`.
Rows = years, columns = Jan…Dec **+ Year (annual return) + Sharpe** summary
columns; diverging conditional formatting on the month cells (VegaExpr /
pre-computed hex). The Outperformance tab uses the shared benchmark selector.

## 8. Workstream E — Section 3 (analytics charts, tabbed)

- **Weekly scatter:** strategy weekly returns (x) vs benchmark weekly returns
  (y) with an **OLS regression line** (`ols_fit` → second `Scatter` trace) and
  a beta / R² annotation.
- **Histogram vs benchmark:** reuse the overlay pattern — strategy + benchmark
  daily returns.
- **Factor scatter:** the **selected strategy's monthly points only** — x =
  corr to the equity risk premium, y = corr to the term premium
  (`monthly_factor_correlations`), marker color/size = that month's
  risk-adjusted return. Benchmarks may be overlaid as their own monthly point
  series; **no other strategies**. The v0.7.0 factors it consumes are shipped
  (`src/stats/factors.py`).
  - *Definitional note:* the per-month correlation window (within-month daily
    vs a trailing rolling window sampled monthly) is a build-time choice;
    default to a trailing rolling window for stability.
