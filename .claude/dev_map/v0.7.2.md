# v0.7.2 — Platform performance table: remove Since-Inception

> **Status:** Not started. Documentation only — the roadmap the v0.7.2 cycle is
> executed against.
> **Depends on:** v0.7.0 (the all-catalog Platform grid with its z-score column
> and the `universe_perf` / `_build_universe_frame` pipeline).
> **Theme:** trim the all-catalog Platform performance grid by removing the
> **Since-Inception** supercolumn, leaving Info → Z-Score → 1Y / 3Y / 5Y.

## 1. Summary & non-goals

The Platform tab's full-width all-catalog grid currently carries a **Since
Inception (SI)** supercolumn — Return / Vol / Sharpe / Max DD over each index's
full valid history — to the right of the 1Y / 3Y / 5Y windows. v0.7.2 removes
it: the SI block adds width and its full-history window is the least
comparable across indices of differing ages. The grid keeps the Info block, the
dynamic z-score column, and the 1Y / 3Y / 5Y performance windows.

**Non-goals (hard constraints):**

- **Platform-tab-only.** The Multi-Strategy selected-strategy grid already uses
  `perf_table` (1Y / 3Y / 5Y only, no SI) — it is unaffected.
- **No change to the z-score column, conditional formatting, sort order, or the
  Info block.**
- **No BQL / data-fetch change.**

## 2. Motivation (current state, with refs)

- `src/stats/performance.py` `universe_perf` concatenates `perf_table(...)`
  (1Y / 3Y / 5Y blocks) with `since_inception_perf(...)`, which returns
  MultiIndex columns `("SI", {Return|Vol|Sharpe|Max DD})`.
- `src/layout/grids.py` `_build_universe_frame` orders periods
  `["1Y", "3Y", "5Y", "SI"]`, so SI lands as the rightmost supercolumn.
- The SI column widths flow through `_build_perf_column_widths` / the `PERF_*`
  constants for the all-catalog grid.

## 3. Workstream A — Drop the SI supercolumn

- In `src/stats/performance.py`, stop concatenating `since_inception_perf` into
  `universe_perf` (so the frame returns only the 1Y / 3Y / 5Y windows); update
  the `universe_perf` docstring accordingly.
- In `src/layout/grids.py` `_build_universe_frame`, drop `"SI"` from the
  `period_order` list so nothing renders the block even if a stray SI column
  appears.
- Verify `_build_perf_column_widths` / `PERF_*` carry no SI-keyed widths after
  the change (remove any that are now dead).
- **Keep `since_inception_perf` as a tested pure stats util** (now unwired) to
  minimize churn — it remains a documented metric in `CLAUDE.md`'s stats map.
  *(Alternative: delete the function, its unit test, and its `CLAUDE.md` mention.
  Recommended path is to keep it — it's a harmless, covered utility that a later
  cycle may reuse.)*

## 4. Files touched (when implemented)

- `src/stats/performance.py` — `universe_perf` no longer appends SI (docstring).
- `src/layout/grids.py` — `_build_universe_frame` period order; width cleanup.
- `tests/test_stats.py` — drop the assertion that `universe_perf` includes an SI
  block (and adjust any column-set expectation).
- `CLAUDE.md` — Platform-tab description and the `universe_perf` / grid notes.
