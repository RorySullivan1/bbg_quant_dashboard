# v0.6.5 — Dashboard Styling (Beautiful but Technical)

> **Status:** Shipped. All five workstream PRs (§9) merged into the `v0.6.5`
> integration branch: #70 (A, dark tokens + global CSS), #72 (B, masthead),
> #73 (C, loading overlay + staged progress), #74 (D, buttons & widgets),
> #75 (D, dark grid theme); closed out by the release wrap-up (`.meta/VERSION`
> → 0.6.5, CLAUDE.md notes, retire `TabButtonTone`, CI branch filter).
> **Depends on:** v0.6.0 (the `layout/` package, `data/templates/` +
> `render_template`, refreshed style tokens, and the global CSS injection
> point). Land v0.6.0 first.
> **Theme:** make the dashboard *beautiful but technical* — a cohesive dark,
> terminal-grade look with a significant title, refined buttons/widgets, and
> a real loading experience.

## 1. Summary & non-goals

The charts already render dark (Bloomberg/Barclays blend); the surrounding
chrome is still light, the title is a small hardcoded bar, and a permanent
status banner sits under it. v0.6.5 unifies the look: dark technical chrome,
a bold masthead title, polished controls, and — the headline UX change — the
static status banner is **replaced by a full-screen dimmed loading overlay
with a staged progress bar that disappears once data is loaded**.

**Non-goals (hard constraints):**

- **No analytics or behavior change** beyond the loading UX. Filters,
  panes, grids, and all computed values are untouched.
- **Preserve the data contracts** (`CLAUDE.md`): one BQL call per session,
  the per-trading-day parquet cache, benchmarks scoped to rolling tabs,
  narrow-only filters (no recompute).
- **No new runtime dependencies.** Styling uses injected CSS + existing
  ipywidgets/plotly/ipydatagrid; templating uses v0.6.0's `{{placeholder}}`
  `render_template` (no jinja2).
- **All colors/sizes come from `src/style.py` tokens** — no new inline hex.

## 2. Motivation (current state, with refs)

| Problem | Where | Why it hurts |
|---|---|---|
| Title is small & hardcoded | `BANNER_HTML` `layout.py` L92–100 (`font-size:22px; font-weight:600`, inline hex, not even `FontSize.HERO`) | Doesn't read as a significant product masthead; bypasses tokens. |
| Permanent status banner | `_status_banner`/`_render_status` L115–130, mounted as the 2nd VBox child (`status_w` L521, L1161+) | Always-present "Loaded…" bar is clutter; no sense of loading progress. |
| No progress indicator | load flow L786–803 / L1113–1144 pushes text only via `_set_status`/`_format_loaded` (L523–543) | Users get "Fetching…" then a wait with no feedback. |
| Light chrome vs dark charts | chrome uses `Color.BRAND_NAVY`+slate light scale; charts use `CHART_BG #0d1117` | Visual mismatch — not the cohesive "technical" feel wanted. |
| Flat buttons/widgets | `_make_tab_button`/`_style_tab_button` L165–184; Refresh L503–510; Clear L511–520 (ipywidgets default) | No hover/active states; Clear buttons unstyled; controls feel utilitarian. |
| No global CSS hook | grep: no `<style>` injection anywhere | Can't do `:hover`, scrollbars, overlay, or grid theming with `.style` alone. |

## 3. Workstream A — Dark technical design system

- **Extend `src/style.py` `Color`** with a dark-chrome group (aligned with
  the chart palette): `CHROME_BG` (near-black, ≈ `CHART_BG #0d1117`),
  `SURFACE` (raised panel), `SURFACE_2`, `BORDER`, `TEXT`, `TEXT_MUTED`,
  `ACCENT` (Bloomberg orange `#FFA000`), `ACCENT_2` (Barclays cyan
  `#00B5E2`).
- **Global CSS injection** — new template `data/templates/app_css.html`
  (`<style>…</style>`), mounted once as a `W.HTML` at the top of the app
  VBox. It defines the classes the rest of v0.6.5 hangs off:
  - base font + `CHROME_BG` background, dark text;
  - custom slim scrollbars;
  - button hover/active/focus states;
  - the loading-overlay + progress-bar classes (Workstream C);
  - dark overrides for the accordion header, dropdowns, checkboxes, the
    search box, and date pickers;
  - ipydatagrid dark theming (Workstream D).
  Widgets opt in via `widget.add_class("…")` (the DOMWidget API) — this is
  the mechanism ipywidgets lacks natively. CSS values are produced from
  tokens via `render_template` context, so `style.py` stays authoritative.
- **Type scale** — token-driven (see §7); no inline sizes.

## 4. Workstream B — Title masthead

Make the title *significant*:

- New `FontSize` token `TITLE` (≈ 30–36px), font-weight **800**, tightened
  letter-spacing, and an accent rule/underline in `ACCENT`.
- Larger logo; subtitle becomes an uppercase technical caption
  (`FontSize.MICRO`, letter-spacing, `TEXT_MUTED`).
- Move `BANNER_HTML` into `data/templates/banner.html` (per v0.6.0),
  rendered via `render_template(banner, title=…, subtitle=…, navy=…, …)`
  with token context — no hardcoded hex.

## 5. Workstream C — Loading overlay + staged progress

**Remove** the permanent `status_w` banner from the VBox flow. Replace with
a dynamic overlay:

- **Overlay** — `data/templates/loading_overlay.html`: a dimmed backdrop
  (`position:fixed; inset:0; z-index` via injected CSS) with a centered
  card showing the app title, a **stage label**, and a **progress bar**
  (custom CSS-classed HTML bar for the look; `W.IntProgress` acceptable if
  styled). Built in `layout/chrome.py`.
- **Stage → % mapping** (driven from the real load stages in
  `builder.py`):
  | % | Stage | Label |
  |---|---|---|
  | 0 | start | "Initializing…" |
  | 25 | after `load_metadata()` | "Loaded N indices" |
  | 60 | during/after `fetch_prices()` | "Fetching prices for N indices…" |
  | 85 | after `_update_universe_grid` | "Building catalog…" |
  | 100 | after `_recompute()` | "Ready" |
- **Dismissal** — at 100%, fade out (CSS opacity transition) then
  `add_class`/`layout.display = "none"`. **Refresh prices** re-shows the
  overlay and re-runs the staged bar. **Error path** keeps the card visible
  with the traceback summary and a red `ACCENT` instead of vanishing.
- **Post-load status** — fold the "Loaded N indices · M trading days ·
  fetched from … in X.Ys" / "from cache" summary into a slim,
  auto-dismissing **toast** (reuse `StatusTone` + `_format_loaded`), so the
  permanent banner is gone but the summary/errors are still surfaced.
- **Technical caveat** — `build_app` is synchronous and `fetch_prices`
  blocks, so to show progress *during* load the builder must `display()`
  the overlay first and push progress/label updates as each stage
  completes (widget comm updates flush to the Voila frontend), then mount
  the dashboard and dismiss the overlay. v0.6.0's `builder.py` /
  `DashboardState` split makes this staging clean; a background-thread load
  is an **optional stretch**. The exact integration point is `build_app`'s
  init sequence (today L786–819) and `_refresh_prices` (today L1113–1144).

## 6. Workstream D — Buttons & widgets polish

- **Hover/active/focus** states for the tab pills and the Refresh (primary)
  button via injected CSS — ipywidgets `.style` can't express `:hover`.
- **Clear buttons** get a defined *secondary* style (outlined/muted) instead
  of the ipywidgets default (L511–520).
- Consistent control heights, rounded corners, and dark styling for
  dropdowns, checkboxes, the search box, date pickers, and the accordion
  header.
- **Dark ipydatagrid theme** for both perf grids (selected + all-catalog)
  so the tables match the charts; keep the existing renderers/column-width
  logic, just retheme via tokens.
