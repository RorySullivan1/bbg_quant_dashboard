# v0.7.5 — Multi-Strategy tab fixes

> **Status:** Not started. Documentation only — the roadmap the v0.7.5 cycle is
> executed against.
> **Depends on:** v0.7.0 (the selected perf grid's `sharpe_heatmap` infra,
> the analysis date-range controls, and the per-pane correlation regime
> controls).
> **Theme:** three independent Multi-Strategy polish items — color-grade the
> selected perf grid's Sharpe cells, replace the analysis date **slider** with
> two side-by-side date boxes, and restructure the correlation
> **Benchmark / Regime** controls.

## 1. Summary & non-goals

Three small, independent fixes to the **Multi-Strategy Analysis** tab:

1. **Sharpe color-coding** in the selected-strategy performance grid, matching
   the Platform all-catalog grid's diverging red→neutral→green Sharpe cells.
2. **Date range without a slider** — drop the `SelectionRangeSlider` and leave
   just the two `DatePicker` boxes, side by side with a hyphen between them
   (like the Characteristics filter's launch-date range).
3. **Correlation Benchmark / Regime controls** — rename the benchmark-reveal
   checkbox to **"Benchmark"**, nest a separate **"Regime"** checkbox under it,
   and replace the Down/Up toggle with a **`>` / `<`** dropdown beside the
   percentile dropdown.

**Non-goals (hard constraints):**

- **No BQL / fetch change.** All three reuse already-fetched data; the
  date-range re-slice still happens on **Refresh prices** only.
- **Platform tab untouched.**
- **Windowing behavior is preserved** (item 2): overlap-bounds derivation,
  basket-change reset vs same-basket preserve, min ≤ max clamping, Clear-all →
  full span.

## 2. Motivation (current state, with refs)

- **Sharpe coloring** — `src/layout/grids.py` `_perf_renderers` /
  `_apply_grid_styling` already accept a `sharpe_heatmap` flag (diverging
  `_diverging_bg_renderer` on Sharpe + Z-Score leaves). The all-catalog grid
  passes `True`; the selected grid's `_update_perf_grid` styling call leaves it
  `False`. The selected grid has Sharpe leaves under 1Y / 3Y / 5Y and **no**
  Z-Score column, so the z-score branch is a harmless no-op.
- **Date slider** — `src/layout/builder.py` builds `range_min_box` /
  `range_max_box` (`DatePicker`) **and** `date_slider`
  (`SelectionRangeSlider`), assembled `[range_min_box, date_slider,
  range_max_box]`, two-way linked via `_set_slider_options` /
  `_on_slider_change` / `_on_range_box`. Bounds come from
  `common_window_bounds`; state lives on `DashboardState.last_sel_key` /
  `sync_guard` / `cur_win_start` / `cur_win_end`. The Characteristics filter
  already uses a `[box, "–", box]` hyphen layout to copy.
- **Regime controls** — `src/layout/panes.py` `_make_analysis_pane` builds
  `heat_regime_chk` (label **"Regime filter"**), `heat_benchmark_dd`, `heat_dir`
  (`ToggleButtons` Down/Up), `heat_pct` (0–100% step 5), with
  `_sync_regime_controls` / `_sync_benchmark_visibility`. The single checkbox
  currently reveals **all three** of {benchmark dd, direction, pct} together.
  `src/layout/builder.py` `_render_heatmap` maps `heat_dir == "Up" →
  direction="up"` else `"down"` into
  `regime_corr_matrix(..., direction, include_benchmark=True)`. In
  `src/stats/risk.py`, `direction="down"` keeps `bench <= quantile(pct)` (worst
  days); `"up"` keeps `bench >= quantile(1 - pct)` (best days).

## 3. Workstream A — Sharpe color-coding in the selected grid

- Pass `sharpe_heatmap=True` from the selected grid's `_apply_grid_styling`
  call in `src/layout/grids.py` `_update_perf_grid` (the all-catalog grid's call
  is the reference). No new infra — the renderer + thresholds already exist.
- Confirm the selected grid's own dark theme / color-swatch column are
  unaffected.

## 4. Workstream B — Date range: two boxes, no slider

- Remove `date_slider` (`SelectionRangeSlider`) and its `options` / `index`
  plumbing from `src/layout/builder.py`.
- Assemble the row as `[range_min_box, "–", range_max_box]` (reuse the
  Characteristics hyphen layout).
- **Preserve windowing:** keep bounds from `common_window_bounds` on Refresh;
  keep basket-change reset vs same-basket preserve via `last_sel_key`; keep
  min ≤ max clamping; keep `sync_guard`; keep `cur_win_start` / `cur_win_end`;
  keep `Clear all` → full span.
- Replace `_set_slider_options` with a **box-bounds setter** (sets the boxes'
  values to the current overlap window, resetting on basket change) and replace
  `_on_slider_change` / `_on_range_box` with **box observers** that clamp the
  pair (min ≤ max) under `sync_guard`. Do not rely on `DatePicker.min/max` if
  the pinned ipywidgets lacks those traits — clamp in the observer instead.
- Remove any slider-only field from `src/layout/state.py`.

## 5. Workstream C — Correlation Benchmark / Regime controls

- **Rename** the checkbox that reveals the benchmark dropdown to **"Benchmark"**
  (today's "Regime filter").
- **Nest** a new **"Regime"** checkbox that is visible only when **Benchmark**
  is checked; ticking **Regime** reveals the regime selection.
- **Replace** the Down/Up `ToggleButtons` with a `Dropdown` of **`>` / `<`**,
  placed next to the percentile dropdown. Map **`<` → `direction="down"`**
  (worst / below-pct tail) and **`>` → `direction="up"`** (best /
  above-(1 − pct) tail) — matching `regime_corr_matrix`'s semantics.
- **Visibility cascade** (extend `_sync_regime_controls` /
  `_sync_benchmark_visibility` in `panes.py`): Correlation-Heatmap selected →
  show **Benchmark** checkbox; Benchmark checked → show benchmark dropdown +
  **Regime** checkbox; Regime checked → show the `>`/`<` dropdown + percentile.
- **Render** (`_render_heatmap` in `builder.py`): apply regime conditioning only
  when **Regime** is checked (parity with today's gated behavior); read the new
  `>`/`<` dropdown for `direction`. Re-wire the live `.observe` set to the
  renamed/added controls.
- *(Non-goal: a "benchmark-included full-sample" mode for Benchmark-on /
  Regime-off — keep scope tight; unchecked Regime = today's plain full-sample
  correlation.)*
