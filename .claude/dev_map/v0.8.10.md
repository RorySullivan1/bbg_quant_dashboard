# v0.8.10 — Startup selection

> **Status:** Shipped — a small follow-up patch into `v0.8.0`. `.meta/VERSION` →
> `0.8.10`.
> **Depends on:** v0.8.9 (the stale-index prune that reset `ticker_w.options`).
> **Theme:** the Multi-Strategy tab should open populated, not empty.

## Problem

v0.8.9's stale-index prune reassigns `state.ticker_w.options` post-fetch; setting
a SelectMultiple's `options` clears its `value`, so the constructor's default
`head(5)` selection was wiped and the Multi-Strategy views opened empty (no
selected-strategy grid rows, blank panes) until the user picked a strategy.

## Change (`src/layout/builder.py`)

- New `_default_selection()` closure: the **top 5 indices by z(1W Sharpe, 1Y)**
  (`rolling_metric_zscore(arp_universe_prices, metric="sharpe", window=WEEK_WINDOW,
  zscore_window=TRADING_DAYS_PER_YEAR).nlargest(5)`), capped at the universe size,
  falling back to the first tickers when the z-score is unavailable.
- Set `state.ticker_w.value = _default_selection()` right after the prune resets
  the options (and once `arp_universe_prices` exists). The existing initial
  `_recompute()` then renders the grid + both panes populated.
- Refresh keeps the user's own selection (it is not reseeded).

## Tests

- `test_smoke.test_startup_selects_top_zscore_and_populates_multi_strategy`: the
  startup `ticker_w.value` equals the top-5 z-ranking, and the selected-strategy
  grid + panes render with data without a Refresh click.
