> **Status:** In progress. Workstream B (stats + factor data layer, PR #84) and
> Workstream A (enhanced all-catalog grid) implemented; PR-1 and PR-2 below
> ticked. Remaining workstreams (C+D / E) still pending.

## 1. Summary & non-goals

Today the Platform tab is just the all-catalog performance grid
(`platform_panel = VBox[universe_header, universe_grid]`, `layout.py`
L732–741). v0.7.0 expands it into three blocks:

1. **Enhanced all-catalog grid** — conditional formatting on the Sharpe
   columns + a **dynamic z-score column** (z-score of a user-selected
   metric/window/lookback; default *z(1M Sharpe, 1Y)*) chosen via three
   dropdowns above the table, with **the table sorted by that column**.
2. **Section 1 — factor-beta scatter** (x = β to a global equity risk
   premium, y = β to a global bond term premium), one point per strategy,
   colored by asset class.
3. **Section 2 — treemap** grouped by asset class, **sized** by *z(6M
   Sharpe, lookback)* and **colored** by *z(1M Sharpe, lookback)*.

Sections 1 & 2 sit under a shared **6M / 1Y / 3Y / 5Y** lookback selector
that drives both.

**Non-goals (hard constraints):**

- **The Multi-Strategy Analysis tab is untouched.**
- **One BQL call per session is preserved.** The new factor tickers (§9)
  **ride the single `fetch_prices` request** exactly like the existing
  benchmarks — *no second BQL call*. Every Platform analytic computes live
  from the already-fetched `arp_universe_prices` / `universe_prices`;
  dropdowns and lookback buttons **re-slice the cache only** (like the
  Quantitative filter), never refetch.
- **No analytics change** to existing grid columns; all colors/sizes from
  `style.py` tokens.

## 2. Motivation

The Platform tab is the whole-catalog landing view but is currently a flat
table. Clients want to see, at a glance: which strategies are showing
unusual relative strength (time-series z-scores), how each strategy is
positioned against the two dominant macro premia (equity risk premium, bond
term premium), and a compact health map across asset classes.

## 3. Current state (grounded, with refs)

- **Grid:** `_universe_grid` (L1435–1443) + `_update_universe_grid`
  (L1446–1481) — MultiIndex columns: Info block + 1Y/3Y/5Y/SI ×
  Return/Vol/Sharpe/Max DD. **No sort config today.**
- **Conditional-format mechanism exists:** `_perf_renderers` (L1402–1429)
  already binds `background_color=VegaExpr("cell.value")` for the chart-color
  swatch — a diverging `VegaExpr` on Sharpe leaves is the same mechanism.
- **Z-score:** `sharpe_zscore(returns, window, zscore_window)` (`stats.py`
  L164–174) returns the scalar z-score of the latest rolling-`window` Sharpe
  vs its trailing `zscore_window` history → *z(1M Sharpe,1Y)* =
  `sharpe_zscore(returns, window=21, zscore_window=252)`. Only `rolling_sharpe`
  (L156–161) exists; other metrics need rolling versions.
  `TRADING_DAYS_PER_YEAR=252`.
- **Beta:** `ann_beta(returns, benchmark_returns, years)` (L251–268) =
  cov/var over a sliced window — reusable for factor betas.
- **Benchmarks:** `BENCHMARK_TICKERS` (config L36–43) ride the single fetch;
  `bql_client` fetches **only `px_last`** (no yields/rf → premiums are
  return proxies).
- **Plotly:** `go` only; scatter pattern at `_scatter_chart`/`_update_scatter`
  (L1568–1642). No `Treemap` yet.
- **Asset class:** per-ticker `asset_class` in metadata (`data.py`
  COLUMN_MAP) — groups the treemap and colors the scatter.
- **Pill pattern:** `_make_tab_button` (L172–184) / `W.ToggleButtons` for the
  lookback selector.

## 4. Workstream A — Enhanced all-catalog grid

- **Conditional formatting** on every Sharpe leaf: a diverging `VegaExpr`
  background (e.g. red < 0 → neutral ≈ 0 → green high), added in
  `_perf_renderers` (matches on the `Sharpe` leaf like today).
- **Dynamic z-score column** appended under a new `("Z-Score", "<metric>
  <win>/<lb>")` supercolumn, with **three dropdowns above the grid**:
  - **Metric** — Sharpe / Sortino / Return / Vol (default **Sharpe**)
  - **Window** (short metric window) — 1M / 3M / 6M (default **1M**)
  - **Lookback** (z normalization) — 1Y / 3Y / 5Y (default **1Y**)
- **Sort:** pre-sort the combined DataFrame by the z-score column
  (descending) before `grid.data = …`, so display order = the ranking
  regardless of grid UI sort.
- Dropdown changes recompute only this column from cache (no BQL).

## 5. Workstream B — stats additions

- Generalize the `sharpe_zscore` pattern into
  `rolling_metric_zscore(prices, *, metric, window, zscore_window)` →
  scalar per ticker; add rolling helpers `rolling_return`,
  `rolling_volatility`, `rolling_sortino` next to `rolling_sharpe`.
- Factors from the new tickers: `equity_risk_premium(prices)` and
  `term_premium(prices)` → daily factor-return series (ERP ≈ equity-benchmark
  return − short-rate proxy; term premium ≈ long-govt return −
  T-bill/short-rate proxy). `factor_beta(returns, factor_returns, years)` =
  thin wrapper over `ann_beta`.
- `platform_treemap_frame(prices, meta, *, lookback)` → per-ticker
  asset_class + size-z + color-z.

## 6. Workstream C — shared lookback selector

A **6M / 1Y / 3Y / 5Y** pill/toggle group (reuse `_make_tab_button` or
`W.ToggleButtons`) above the two sections. Its value is the **normalization
lookback** for the treemap z-scores **and** the **beta window** for the
scatter. The short metric windows (6M for treemap size, 1M for treemap
color) are fixed.

> **Reconciliation note.** The original ask was *size = z(6M Sharpe, 3Y)* and
> *color = z(1M Sharpe, 1Y)* — two different lookbacks. Per the confirmed
> "drive both sections" decision, v0.7.0 uses **one shared, selectable
> lookback** for both treemap channels and the scatter (default **1Y**),
> keeping **6M** (size) and **1M** (color) as the fixed short windows. Adjust
> the default button here if a 3Y size-lookback is preferred.

## 7. Workstream D — Section 1: factor-beta scatter

`go.Scatter` `FigureWidget` (existing pattern, `batch_update`):

- **x** = `factor_beta(strategy, equity_risk_premium, lookback)`
- **y** = `factor_beta(strategy, term_premium, lookback)`
- One marker per strategy, **colored by asset class** (see §10).
- Hover: name · asset class · ERP β · term β.
- Dashed zero lines on both axes via `layout.shapes` with `xref/yref`
  (reuse the `_h_ref` idea, extended for a vertical line).
- Beta window = the selected lookback (Workstream C).

## 8. Workstream E — Section 2: asset-class treemap

`go.Treemap` `FigureWidget`:

- `labels` = ticker, `parents` = asset class (two-level hierarchy).
- **`values`** = size-z = *z(6M Sharpe, lookback)*.
- **`marker.colors`** = color-z = *z(1M Sharpe, lookback)* on a diverging
  colorscale centered at 0.

> **Design note.** Treemap `values` must be non-negative, but z-scores can be
> negative. Size via a shift transform (`z − min(z) + ε`) or percentile rank
> so the relative ordering is preserved; **color uses the raw z** on the
> diverging scale (negative = cool, positive = warm).

## 9. Data-layer change — factor tickers

Add ERP / term-premium **factor tickers** to `config.py` (a new
`FACTOR_TICKERS` list, or extend `BENCHMARK_TICKERS`) so they ride the single
`fetch_prices(arp + benchmarks + factors, …)` call. Update `_mock_prices` in
`bql_client.py` to cover them deterministically, and update the `CLAUDE.md`
BQL/benchmark conventions. Candidate proxies (exact tickers chosen at build
time, price/total-return only):

- a **long-duration Treasury** total-return index,
- a **T-bill / short-rate** total-return index,
- an **equity benchmark** (SPX/MXWO already present).

Whole-catalog ARP views must continue to exclude benchmark/factor columns
(`arp_universe_prices = universe_prices.reindex(columns=meta["ticker"])`).
