# v0.6.0 — Refactoring & Optimization

> **Status:** In progress — PR #1 (lint/format baseline) landed on the
> `v0.6.0` integration branch; #2–#7 outstanding. This is the roadmap the
> v0.6.0 cycle is executed against.
> **Integration branch:** `v0.6.0` (feature branches merge into it).
> **Theme:** clean up, centralize, and "containerize" the codebase so
> edits stay isolated and functionality is generalized — no new features.

## 1. Summary & non-goals

`v0.5.0` shipped a feature-complete dashboard, but `src/layout.py` has
grown into a 1,930-line monolith with hand-built HTML, duplicated chart
and grid code, and a `build_app()` that threads state through a pile of
closures. v0.6.0 pays that debt down: turn `layout` into a package of
isolated components, move HTML into templates, collapse the duplication,
make state explicit, and stand up tests + linting so future work is safe.

**Non-goals (hard constraints):**

- **No behavior or visual change.** The rendered dashboard must look and
  act identically on mock prices before and after. This is a pure
  refactor.
- **No new runtime dependencies.** HTML templating reuses the existing
  `{{placeholder}}` `str.replace` pattern — *no jinja2*. (Dev-only tools
  like `pytest`/`ruff`/`black` are allowed.)
- **Preserve the data contracts** documented in `CLAUDE.md`: one BQL call
  per session, the per-trading-day parquet cache, benchmarks scoped to
  the rolling tabs, and filter controls that narrow-only (no recompute).

## 2. Motivation (concrete debt, with locations)

| Problem | Where | Why it hurts |
|---|---|---|
| Monolithic UI module | `src/layout.py` — **1,930 lines**, ~43 functions | Every UI edit touches one giant file; hard to isolate or review. |
| `build_app` god-function | `layout.py` L372–1178 (~600 lines, ~15 nested fns) | State threaded via closures/`nonlocal` (`universe_prices`, `arp_universe_prices`, `init_errors`, `active_filter`); hard to follow or test. |
| Inline hand-built HTML | `BANNER_HTML` L92–100, `_render_status` L124, `_section_label` L547, highlight cards L1896–1918, `_render_error` L1924, grid headers L717/733, quant-row label L435, date dash L578 | HTML/CSS mixed into Python; can't edit copy/markup without touching code. |
| Duplicated chart code | 8 `_<name>_chart()` / `_update_<name>()` pairs; 5 line-style updaters share the same empty-check → iterate cols → `_palette_color`+`_short_ticker` → `batch_update` shape | Same bug must be fixed 5–8×; new chart = copy-paste. |
| Duplicated dropdown | benchmark `Dropdown` built verbatim 3–4× in `_make_analysis_pane` L215–235 | Drift between panes; no single source. |
| Duplicated grid code | `_update_perf_grid` & `_update_universe_grid` repeat info-block + swatch + MultiIndex + `_perf_renderers` | Two places to keep in sync. |
| Dead code | `AssetClassColor` + `ASSET_CLASS_COLORS`, `style.py` L152–171 | Never imported anywhere — charts use positional `LINE_PALETTE`. Pure noise. |
| No safety net | no `tests/`, no linter/formatter config, partial type hints | Nothing catches a regression during a refactor of this size. |

## 3. Workstream A — `layout/` becomes a package

Replace `src/layout.py` with a `src/layout/` package. `__init__.py`
**re-exports `build_app`** so the public import surface is unchanged
(`from src.layout import build_app`, and `dashboard.ipynb` stays a
one-liner). Fine-grained split:

| Module | Owns (from today's `layout.py`) |
|---|---|
| `layout/__init__.py` | `from .builder import build_app` re-export only |
| `layout/theme.py` | `_chart_layout`, `_h_ref`, `_palette_color`, `_short_ticker`, `_sentiment_color`, `CHART_HEIGHT` |
| `layout/chrome.py` | `_banner`, `_status_banner`, `_render_status`, `_make_tab_button`, `_style_tab_button` |
| `layout/filters.py` | `_checkbox_group`, `_section_label`, quant-row builders, clear-section / clear-all logic |
| `layout/panes.py` | `_make_analysis_pane` + the 9 `_*_chart()` factories |
| `layout/charts.py` | the 8 `_update_<chart>()` updaters |
| `layout/grids.py` | `_perf_grid`/`_update_perf_grid`, `_universe_grid`/`_update_universe_grid`, `_info_block`, `_perf_renderers`, width helpers (`_build_perf_column_widths`, `_PERF_*`) |
| `layout/html.py` | template loading + render helpers (Workstream B) |
| `layout/builder.py` | `build_app` + `_recompute` / `_render_pane` / `_refresh_prices` orchestration |

Keep `from __future__ import annotations` in each module; imports between
submodules are explicit and acyclic (theme/chrome/html have no internal
deps; panes→theme; charts→theme; grids→theme+html; builder→everything).

## 4. Workstream B — HTML templating (no new deps)

- Create `data/templates/` and move each inline HTML block into its own
  `*.html` file with `{{placeholder}}` slots: `banner.html`,
  `status.html`, `section_label.html`, `highlight_card.html`,
  `highlights_wrapper.html`, `error_box.html`, `grid_header.html`,
  `quant_row_label.html`.
- Generalize the existing `_load_disclaimer` into one
  `render_template(name, **ctx) -> str` in `layout/html.py` that reads
  `data/templates/<name>.html` and does `{{key}}` → value substitution.
  The current disclaimer loaders (`_load_disclaimer`,
  `_load_weekly_commentary`) become thin callers of it.
- **Style tokens stay authoritative in `src/style.py`.** Templates carry
  no hardcoded hex/fonts — colors and font stacks are passed in via the
  context dict (e.g. `{{navy}}`, `{{mono}}`, `{{label_size}}`), so a token
  change in `style.py` still propagates. `html.escape` of dynamic text
  happens before substitution, exactly as today.

## 5. Workstream C — dedup / generalize helpers

- `_update_line_series(fig, df, meta, *, y_format, title, ref_y, hover)`
  in `layout/charts.py` — collapses the 5 line-style updaters
  (`_update_line`, `_update_outperformance`, `_update_sharpe_line`,
  `_update_drawdown`, `_update_rolling_ref`) onto one engine; each keeps a
  thin wrapper for its title/format/ref-line specifics.
- `_make_benchmark_dropdown(description, *, default=DEFAULT_BENCHMARK)` in
  `layout/panes.py` — single factory for the 3–4 benchmark dropdowns.
- `_build_info_block(tickers, meta)` + `_apply_grid_styling(grid, columns)`
  in `layout/grids.py` — shared by both grid updaters (info block, color
  swatch, MultiIndex columns, `_perf_renderers`).

Each helper's docstring lists the call sites it replaces. No change to
output — verified by the smoke test (Workstream E).

## 6. Workstream D — explicit state object

Introduce a `DashboardState` `@dataclass` (in `layout/builder.py` or a
small `layout/state.py`) holding what `build_app` currently keeps in
closures/`nonlocal`: `universe_prices`, `arp_universe_prices`,
`init_errors`, `active_filter`, and the key widget handles
(`ticker_w`, `status_w`, grids, the two panes). `_recompute`,
`_render_pane`, and `_refresh_prices` take the state explicitly instead of
closing over it. This makes the data flow legible and unit-testable
without standing up the whole widget tree.

## 7. Workstream E — tests + smoke test

- Add `tests/` and a dev `pytest` dependency.
- **Smoke test:** `build_app()` renders end-to-end on the deterministic
  mock-price fallback without raising, and returns a `VBox` with the
  expected top-level children. This is the regression guard for the whole
  refactor.
- **Unit tests** for `src/stats.py` pure functions against small fixed
  frames: `cum_perf`, `ann_return`, `ann_volatility`, `ann_sharpe`,
  `drawdown_series`, `corr_matrix`, `regime_corr_matrix`,
  `quant_metrics_table`, `zscore_cross_section`, `historical_var`, `rsi`.
- Wire `pytest` into `requirements.txt` (dev section) and document
  `pytest -q` in `CLAUDE.md` testing notes.

## 8. Workstream F — lint / format / types

- Adopt **ruff** (lint) + **black** (format, 88-char) across `src/` and
  `tests/`; add `[tool.ruff]` / `[tool.black]` config (a `pyproject.toml`
  for tooling config only — *not* a packaging migration).
- Add/repair **type hints** on public signatures touched during the split.
- Document `ruff check src tests` and `black src tests` in `CLAUDE.md`.
- **Stretch:** a pre-commit hook and/or a GitHub Actions CI job running
  `ruff` + `black --check` + `pytest` on PRs into `v0.6.0`.

## 9. Workstream G — dead-code removal

- Remove `AssetClassColor` and `ASSET_CLASS_COLORS` (`style.py` L152–171)
  — confirmed unused (no import in `layout.py`; charts color positionally
  via `LINE_PALETTE`). Update the `CLAUDE.md` note that currently calls
  them out as "defined but currently unused".
- **Optional stretch — `stats.py` sub-package.** `stats.py` is 466 lines
  / 40+ functions. A future `stats/` split into `performance` / `risk` /
  `rolling` with an `__init__` re-export (flat public surface) is noted
  but *not required* for v0.6.0 — the core refactor must not block on it.
