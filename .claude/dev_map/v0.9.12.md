# v0.9.12 — Single Strategy Filter + Code-Review & Optimization

> **Status:** In progress on the `v0.9.12` integration branch (cycle active off
> `0.9.11`). Workstream 1 (the Single Strategy "Filters" accordion) has shipped;
> Workstream 2 (the code-review & optimization pass) is underway.
> **Depends on:** v0.9.0 (the Single Strategy tab and its picker/panes), v0.6.0
> (the `layout/` package + templates) — both shipped.
> **Theme:** make the Single Strategy tab filterable and pay down review debt —
> tighten the docs, fix the CI trigger, and queue the follow-up refactors.

## 1. Summary & non-goals

Two workstreams:

1. **Single Strategy "Filters" accordion (shipped)** — a reusable filter panel
   lifted out of the Multi-Strategy tab into `src/layout/filter_panel.py`
   (`make_filter_panel`) and wired onto the Single Strategy tab, where it
   **narrows the strategy picker live** off the cache (no Refresh-prices button,
   no BQL) and auto-selects the first still-matching strategy when the picked one
   is filtered out.
2. **Code-review & optimization pass (in progress)** — a review sweep whose
   first deliverables are **documentation comprehensiveness fixes** (the repo
   memory under `.claude/context/`, the architecture map, the dev-map) and the
   **CI trigger fix** (`.github/workflows/ci.yml` triggering on the version
   integration branches rather than a single stale branch). The larger refactors
   surfaced by the review are tracked as GitHub issues tagged `v0.9.12-review`
   rather than done inline this cycle.

**Non-goals (hard constraints):**

- **No new BQL call** — the filter panel slices the already-cached
  `state.arp_universe_prices` / `state.universe_prices`, same as Multi-Strategy.
- **No behavior change to the Platform or Multi-Strategy tabs** — the
  Multi-Strategy tab keeps its own inline filter copy for now (its
  de-duplication onto `make_filter_panel` is a tracked follow-up, not this
  cycle).
- **No new runtime dependencies.**

## 2. Motivation

The Single Strategy tab (v0.9.0) shipped with a single-select picker over the
**whole** universe — with a large catalog the user cannot narrow the picker the
way the Multi-Strategy tab's filter panel allows. Meanwhile the review found the
repo-memory docs had drifted (stale symbol names, a MultiIndex grid description
that no longer matches the flattened grids, a CI branch that no longer exists),
so the same pass tightens the docs and CI and inventories the remaining
refactors.

## 3. Current state (grounded, with refs)

- **Multi-Strategy filter UI** lives inline in `build_app`'s closures in
  `src/layout/builder.py` (pill bar over swappable checkbox groups / the
  Characteristics launch-date + currency view / the quant-threshold rows, with
  Clear section / Clear all). The Single Strategy tab (`single_strategy.py`) had
  only the single-select picker + shared benchmark selector + overlay toggle.
- **Quant-threshold slicing** reuses `quant_metrics_table` /
  `zscore_cross_section` over the cached prices (no BQL).
- **CI** (`.github/workflows/ci.yml`) triggered on a single stale integration
  branch, so newer `v*` branches were not exercised.

## 4. Workstream 1 — Single Strategy "Filters" accordion (shipped)

A **reusable "Filters" accordion** extracted into
`src/layout/filter_panel.py` (`make_filter_panel(meta)`): the pill bar (Asset
Class / Category / Theme / Return Type / Characteristics / Quantitative) over
swappable checkbox groups / the launch-date + currency Characteristics view /
the nine `≥`/`≤` quant-threshold rows, plus Clear section / Clear all.
Selection-agnostic — it exposes `.root`, `.inputs`, and `matching(meta, state)`
(the tickers passing the current filter state; categorical + Characteristics via
`apply_filters`, then the quant thresholds via the cached
`state.arp_universe_prices` / `state.universe_prices`, same `_quant_keep` logic
as Multi-Strategy). Wired onto the Single Strategy tab in `builder.py` so
toggling any filter box **re-renders the tab immediately off the cache** (no
Refresh-prices button, no BQL) and auto-selects the first still-matching
strategy when the picked one is filtered out. Tested in
`tests/test_single_strategy_filter.py`.

## 5. Workstream 2 — Code-review & optimization pass (in progress)

Deliverables this cycle:

- **Documentation comprehensiveness fixes** — correct the drifted repo-memory
  docs (`.claude/context/*`, the architecture map's `src/stats/` inventory and
  grid descriptions, the dev-map index) against the actual code.

  units.
- **Per-pane benchmark-render dedup** across the analysis panes.
- **Low-risk cleanups** identified during the sweep.
