# v0.8.0 — Key Highlights Rework

> **Status:** In progress — all three workstream PRs open into the `v0.8.0`
> integration branch (A #99 stats, B #100 builders, C this PR: layout). The
> `.meta/VERSION` bump + the README roadmap `[x]` are deferred to the
> end-of-cycle release commit once the three land.
> **Depends on:** v0.6.0 (`layout/` package, `commentary` module, HTML
> templates) and v0.6.5 (dark theme).
> **Theme:** turn the single mixed "Key Highlights" grid into **two
> side-by-side panels** — a monthly **statistical superlatives** board on the
> left and a **new launches** board on the right.

## 1. Summary & non-goals

Today's "Key Highlights" is one auto-fit grid mixing 5Y performance extremes,
correlation pairs, and "recently launched" cards. v0.8.0 splits it into two
purpose-built panels:

- **Left — Market Superlatives · Past Month:** the most extreme index across
  the whole catalog for each of a set of professional superlatives over the
  trailing ~1 month ("Top performer", "Longest bull run", "Strongest trend",
  "Best risk-adjusted", …).
- **Right — New Launches:** new indices with the metadata around each launch
  (informative of platform developments).

**Non-goals (hard constraints):**

- **Whole-catalog only** — commentary is always whole-catalog (never the
  selected subset), unchanged.
- **No analytics change elsewhere; no new runtime deps.** Render through the
  v0.6.0 HTML templates; all colors/sizes from `style.py` tokens.
- **No extra BQL call** — driven from `_recompute` off the already-fetched
  `arp_universe_prices`.
- The existing **Weekly Commentary** block stays separate, above the panels.

## 2. Motivation (current state, with refs)

| Problem | Where | Why it hurts |
|---|---|---|
| One mixed grid, 5Y window | `_render_highlights` `layout.py` L1885–1919; `build_highlights` `commentary.py` L12–133 | Launches are buried among stats; nothing says "what's notable *this month*". |
| Launches inline as cards | launch logic `commentary.py` L121–131 (`NEW_LAUNCH_DAYS=30`) | New launches deserve their own informative panel with full metadata. |
| No streak / trend stats | `stats.py` has none | "Longest bull run" / "Strongest trend" need new functions. |

Building blocks that exist: `daily_returns`, `drawdown_series`,
`_slice_last_years(df, years)` (L188–194), `ann_return`/`ann_volatility`/
`ann_sharpe`/`max_drawdown`, `rsi`, `corr_matrix`, `since_inception_perf`.
A 1-month window = `_slice_last_years(df, 21/252)`. Launch metadata
(`data.py` COLUMN_MAP): `name`, `asset_class`, `category`, `theme`,
`return_type`, `currency`, `live_date` (datetime).

## 3. Workstream A — New stats (`stats.py`)

- `longest_up_streak(returns, *, window_days=21)` → per-ticker longest run of
  consecutive positive daily returns within the window. Powers **Longest bull
  run**.
- `trend_strength(prices, *, window_days=21)` → per-ticker OLS slope of log
  price vs time over the window, scaled by goodness-of-fit (slope·R² or
  t-stat) so a clean, persistent uptrend ranks above a noisy one. Powers
  **Strongest trend**.
- `period_return(prices, *, window_days=21)` → simple cumulative return over
  the window (intuitive "past-month return", **not** annualized) for the
  performer cards.
- Reuse `ann_sharpe` / `ann_volatility` / `max_drawdown` / `rsi` /
  `corr_matrix` over the 1M slice for the rest.

All three new helpers get `pytest` unit tests (v0.6.0) against small fixed
frames, including degenerate cases (flat series, short history → NaN/0).

## 4. Workstream B — Split the builder (`commentary.py`)

Replace `build_highlights` with two focused builders:

- `build_superlatives(meta, prices, returns, *, window_days)` → one card per
  superlative = the **most extreme** index (argmax/argmin), each card
  `{title, name, ticker, value (formatted), sentiment, detail}`. Skips names
  with insufficient history (NaN) rather than erroring; breaks ties
  deterministically (e.g. by ticker).
- `build_launch_cards(meta, prices, *, as_of, new_launch_days)` → new-launch
  entries: `name`, `ticker`, `asset_class · theme · currency`, `live_date`,
  **days-since-launch**, and **since-inception return** (`since_inception_perf`).
  Sorted newest-first.

**Superlative set (whole-catalog, trailing 1M):**

| Card | Metric | New? | Sentiment |
|---|---|---|---|
| Top performer | max `period_return` | reuse | POSITIVE |
| Weakest performer | min `period_return` | reuse | NEGATIVE |
| Strongest trend | max `trend_strength` | **new** | POSITIVE |
| Longest bull run | max `longest_up_streak` | **new** | POSITIVE |
| Best risk-adjusted | max `ann_sharpe(1M)` | reuse | POSITIVE |
| Steadiest | min `ann_volatility(1M)` | reuse | NEUTRAL |
| Most resilient | max (least-negative) `max_drawdown(1M)` | reuse | POSITIVE |
| *Nice-to-have:* Strongest momentum | max `rsi` | reuse | POSITIVE |
| *Nice-to-have:* Best diversifier | min mean `corr_matrix` row | reuse | NEUTRAL |
| *Nice-to-have:* Biggest turnaround | max rebound off the month's low | new (small) | POSITIVE |

The nice-to-have cards are optional — include as many as fit the grid cleanly.

## 5. Workstream C — Two-section layout

Rework `_render_highlights` into an **HBox of two equal-width panels** (flex,
equal height; stacks vertically on narrow widths):

- **Left — "Market Superlatives · Past Month":** a grid of superlative cards —
  the superlative as the label, a big sentiment-colored value, and the winning
  index's name + ticker beneath.
- **Right — "New Launches":** a list of launch cards — name + ticker,
  `asset class · theme · currency`, launch date + "N days ago", and
  since-inception return. Friendly empty-state copy when no launches fall in
  the window.

Mounts where `highlights_w` is today (in `commentary_box`); Weekly Commentary
stays above. Render through v0.6.0 templates (new
`data/templates/superlative_card.html`, `launch_card.html`,
`highlights_two_col.html`); colors/sizes from `style.py` (`Sentiment`,
`Color`, `FontSize`).

## 6. Data flow / state

Still driven from `_recompute` with whole-catalog `arp_universe_prices`,
sliced to the trailing ~21-day window; one HTML rebuild, no extra fetch. The
1M window length is a config constant `SUPERLATIVE_WINDOW_DAYS = 21`.

## 10. Follow-up — v0.8.x Key Highlights polish & interactivity

A post-rework refinement (branch `v0.8.0-highlights-polish-interactive`, PR into
`v0.8.0`):

- **Layout:** Superlatives:New-Launches is now **2:1**; cards shrunk (smaller
  padding, ellipsis-clamped label/name, inline `detail` line dropped) to cut the
  section height; grid `minmax(150px)`.
- **Tooltips:** each card's metric explanation moved to a hover `title` alt-text
  (`description` field) + a `.bbg-superlative:hover` lift in `app_css.html`.
- **More superlatives (10 → 19):** Most volatile, Hardest hit, Lowest tail risk,
  Best Sortino, Highest Calmar, Most oversold, Longest losing streak, Most
  extended / Most below trend (moving-average spread). New stats
  `longest_down_streak` / `ma_spread` in `src/stats/performance.py` (+ tests);
  the rest reuse existing helpers.
- **Interactivity:** a `1W/1M/3M/6M` `superlative_window` ToggleButtons recomputes
  the whole board live from the cache (reusing the Platform lookback-toggle
  pattern, no BQL); errors moved to a dedicated `state.errors_w` so the toggle
  never wipes them.
