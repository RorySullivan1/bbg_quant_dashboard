## 1. Summary & non-goals

Add a **Regime Analysis** tabbed section to the **Platform** tab, inserted
**between the factor scatter and the treemap**. It groups two regime-conditioned
visuals as pill-tabs:

- **Risk vs Return** — the all-catalog per-strategy risk/return scatter
  (annualized vol vs annualized return, colored by asset class), computed over
  only the days in the selected regime bucket.
- **Correlation** — a correlation heatmap over only the regime-bucket days.

Each tab carries its own **regime-type dropdown** (Volatility / Trend /
Liquidity / Rate-level). Selecting a type reveals **conditional sub-dropdowns**;
for **Volatility** that is a VIX-bucket dropdown (`VIX < 15`, `15 ≤ VIX < 25`,
`25 ≤ VIX < 35`, `VIX ≥ 35`), which restricts the chart to days in that bucket.

This release is **structure-first**: the **Volatility** regime is fully wired
end-to-end as the reference implementation; **Trend / Liquidity / Rate-level**
ship as scaffolded dropdowns (present, selectable) whose indicators + buckets +
conditioning are fleshed out in later versions.

**Non-goals (hard constraints):**

- **Whole-catalog (ARP) only**, like the rest of Platform — never the selected
  subset.
- **One BQL call per session unchanged.** The regime indicator(s) ride the
  single startup fetch alongside `BENCHMARK_TICKERS` / `FACTOR_TICKERS`; **no
  second BQL call.** All regime conditioning is a live re-slice of the cache.
- **No new runtime dependencies.** Charts reuse plotly `FigureWidget` + the dark
  chart theme; controls reuse the existing pill-tab + conditional-dropdown
  patterns.
- **Multi-Strategy tab untouched**; the existing factor scatter and treemap are
  unchanged (only repositioned around the new section).
- Only **Volatility** is functional this cycle; the other three regimes are
  inert scaffolding (no fake analytics).

## 2. Motivation

The Platform tab today answers "how do these strategies rank / cluster / expose
to factors overall," but a desk also wants "how does this universe behave *when
vol is elevated* / *in a trending tape* / *when rates are high*." Regime
conditioning is the natural next Platform lens, and the building blocks already
exist — the heatmap's `regime_corr_matrix` already conditions a correlation
matrix on a benchmark-return tail; this generalizes that idea to an explicit,
indicator-driven bucket and applies it to both a scatter and a heatmap.

## 4. Regime model

A config-driven mapping `regime type → indicator ticker → ordered buckets`,
each bucket a `(label, low, high)` half-open `[low, high)` range over the
indicator's daily level (use `±inf` for the open ends).

| Regime | Indicator | Buckets (this cycle) | Status |
|---|---|---|---|
| **Volatility** | `VIX Index` | `VIX < 15` · `15 ≤ VIX < 25` · `25 ≤ VIX < 35` · `VIX ≥ 35` | **functional** |
| Trend | TBD (e.g. % of catalog above its 200d MA, or a trend-index level) | placeholder | scaffold |
| Liquidity | TBD (e.g. a credit-spread or funding proxy) | placeholder | scaffold |
| Rate-level | TBD (e.g. a 2Y/10Y yield index level) | placeholder | scaffold |

The scaffolded regimes render their dropdowns with a single placeholder option
(e.g. "— coming soon —") and leave the chart on the unconditioned (all-days)
view until a later version supplies their indicator + buckets. Picking a regime
whose indicator isn't in the cache must degrade gracefully (unconditioned view,
no traceback).

## 6. Workstream B — regime analytics (`src/stats/`)

- `regime_mask(indicator: pd.Series, low: float, high: float) -> pd.Series` —
  boolean membership mask `(indicator >= low) & (indicator < high)`, NaN-safe
  (`±inf` open ends), generalizing the `regime_corr_matrix` tail mask.
- Scatter side: reuse `ann_volatility` / `ann_return` / `ann_sharpe` over the
  **masked** price/return slice → a per-strategy `{vol, ret, sharpe}` frame
  (factor out the frame-building shared with `_update_scatter`).
- Correlation side: `corr_matrix` over the **masked** returns. **Granularity
  decision (refinable):** aggregate to **asset-class-level** returns first
  (mean per asset class per day) so the heatmap stays readable across the ~50
  ARP tickers, rather than a 50×50 per-ticker matrix; revisit if a per-ticker
  matrix is wanted.
- Guard the degenerate case (a bucket selecting < ~2 days, or an absent
  indicator) → empty frame, mirroring `regime_corr_matrix`'s `< 2 rows` guard.
- **Tests** (`tests/test_stats.py`): `regime_mask` membership incl. open ends and
  NaNs; an empty-bucket case; conditioned corr/vol over a hand-built frame where
  a known bucket changes the result.
