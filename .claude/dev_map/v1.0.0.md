# v1.0.0 — Release Hardening

> **Status:** Planned (owner-driven). Documentation only — the roadmap the
> v1.0.0 cycle is executed against.
> **Caps:** the v0.6.0 → v0.9.0 feature arc.
> **Theme:** the polish pass to a shippable 1.0 — testing, final optimization,
> documentation, compliant legal-disclaimer placement, and enhancements.
> Not a new feature surface; this is hardening + polish.

This is a high-level checklist; the maintainer drives most of it and fills in
specifics as the milestone firms up.

## 1. Testing

- Broaden the v0.6.0 `pytest` suite to cover the stats added across the arc:
  z-score column / factors (v0.7.0), superlatives / `longest_up_streak` /
  `trend_strength` (v0.8.0), `monthly_returns` / `weekly_returns` /
  `calendar_return_table` / `ols_fit` / `monthly_factor_correlations` (v0.9.0).
- Keep the `build_app()` smoke test green; add edge cases — empty selection,
  missing/blank benchmark, NA metadata (incl. missing `description`),
  insufficient history.
- Optional **CI gate**: `ruff` + `black --check` + `pytest` on PRs into the
  integration branch.
- Manual QA checklist: on-terminal (BQL) vs off-terminal (mock) parity across
  all three tabs.

## 2. Final optimization

- Profile end-to-end load; confirm the v0.6.9 in-memory cache + memoized
  derived compute hold across Platform / Multi-Strategy / Single Strategy.
- Verify the **single BQL call** contract still holds with the v0.7.0 factor
  tickers riding along.
- Trim residual redundant computation; consider lazy-building heavy/off-screen
  views where it doesn't hurt the instant-swap UX.

## 3. Documentation

- Finalize `CLAUDE.md`; refresh `README` run/deploy notes (BQuant + Voila).
- Produce an **end-user guide** (use the `user-guide-drafter` skill) and
  **developer docs** (use the `technical-documentation-drafter` skill).
- Add a **CHANGELOG** summarizing the v0.6.x–v0.9.x arc; capture screenshots
  of each tab.

## 4. Legal disclaimer placement

- Ensure the **performance disclaimer** and **legal disclosure** are visible in
  compliance-correct positions — near each tab's performance tables (Platform
  grid, Multi-Strategy perf grid, Single Strategy calendar/perf), not only at
  the page bottom; keep the legal disclosure persistent.
- Confirm `{{start_date}}` / `{{end_date}}` dating via `_load_disclaimer`, and
  that all wording edits stay in `data/*.html` (not Python).
- Final placement and wording reviewed with compliance.

## 5. Enhancements (owner backlog)

Catch-all polish bucket — fill in as desired:

- Accessibility (contrast, keyboard nav, ARIA where feasible in ipywidgets).
- Chart / grid **export** (PNG via the plotly modebar; CSV for grids).
- Shareable / persistable view state.
- Performance-table niceties; any items deferred from earlier versions.

## 6. Release mechanics

- Bump `.meta/VERSION` → `1.0.0`; update the `CLAUDE.md` "Branching" section to
  the new version.
- Merge the v0.6.x–v0.9.x integration work; **tag `v1.0.0`**.

## 7. Exit criteria

- Tests green; `ruff` / `black` clean.
- Disclaimers placed and compliance-reviewed.
- Documentation complete (CLAUDE.md, README, user guide, developer docs,
  CHANGELOG).
- Single BQL call confirmed across all tabs.
- `.meta/VERSION` = `1.0.0` and the release is tagged.
