# v0.8.12 — Chart PNG download for the Bloomberg terminal

> **Status:** Shipped — a small self-contained patch into `v0.8.0`.
> `.meta/VERSION` → `0.8.12`.
> **Depends on:** none (additive; touches no existing chart logic).
> **Theme:** give terminal users a working way to export any chart as a PNG.

## 1. Summary & non-goals

Every chart is a plotly `FigureWidget` carrying the built-in modebar "Download
plot as PNG" camera button. That button is **client-side** (`Plotly.downloadImage`
builds a data-URI and fires a *synthetic* anchor click) — it works in the
browser-based project env / Voila but is **blocked inside Bloomberg's embedded
terminal webview**, so terminal users couldn't get a chart image out.

This release renders the *already-built* figure to PNG **server-side** with
kaleido (no browser download involved) behind a new **"⤓ PNG"** button, and
delivers the result two ways that don't depend on the blocked auto-download:

1. **kaleido + plotly cap** — add `kaleido==0.2.1` (self-contained Chromium, no
   system Chrome needed) and cap `plotly>=5.18,<6` (plotly 6.1+ drops kaleido 0.2
   support and requires a separately-installed Chrome).
2. **Export control** (`src/layout/export.py`) — a reusable `_png_export_control`
   factory: a button that, on click, renders the currently-shown figure to PNG
   bytes and drops an inline `Image` preview + a **user-clicked** `<a download>`
   data-URI link into a sink. A genuine user click frequently succeeds where the
   synthetic auto-download is blocked; the preview is the guaranteed fallback.
3. **Wiring** — one control per Multi-Strategy analysis pane (`panes.py`) and one
   on the Platform analytics card (`builder.py`), each resolving the active
   figure at click time.

**Non-goals (hard constraints):**

- No change to any chart's data, traces, theme, or update path.
- No new BQL calls; export operates purely on the in-memory figure.
- No filesystem dependency (a write-to-disk fallback is noted but not shipped).

## 2. Motivation

A user reported the PNG download button works while developing in the browser
env but fails when the app is loaded inside the Bloomberg terminal — the webview
blocks Plotly's client-side blob/auto-download. They need a way to download a
chart picture from the terminal.

## 3. Current state (grounded, with refs)

- Charts are created as bare `go.FigureWidget(layout=_chart_layout(...))` with no
  `config`/modebar customization — `src/layout/panes.py`, `src/layout/platform.py`.
- The Multi-Strategy pane swaps views in a `W.Box` (`panes.py:_make_analysis_pane`,
  the `stack` / `views` dict); the figure is always the mounted view's first child.
- The Platform analytics card swaps figures in `chart_box` keyed by the active
  inner pill-tab (`builder.py:_activate_platform_tab`).
- Pill-button styling helper to reuse: `chrome.py:_make_tab_button` (`.bbg-pill`).

## 4. Workstream A — server-side PNG export

- New `src/layout/export.py`: `_render_png(fig)` (`fig.to_image(format="png",
  width=PNG_EXPORT_WIDTH, scale=PNG_EXPORT_SCALE)`) + `_png_export_control(get_fig,
  *, filename)`. Render is wrapped in try/except so a kaleido failure surfaces in
  the sink instead of raising out of the click handler.
- Wire into both analysis panes and the Platform analytics card.

## 5. Data-layer / config changes

- `src/config.py` — `PNG_EXPORT_WIDTH = 1200`, `PNG_EXPORT_SCALE = 2`.
- `requirements.txt` — `kaleido==0.2.1`; `plotly>=5.18` → `plotly>=5.18,<6`.
