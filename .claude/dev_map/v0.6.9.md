# v0.6.9 — Optimization & Responsiveness

> **Status:** Not started. Documentation only — the roadmap the v0.6.9 cycle is
> executed against.
> **Depends on:** v0.6.0 (`layout/` package + `DashboardState`) and v0.6.5
> (styling). Lands after v0.6.5, before v0.7.0.
> **Theme:** make the dashboard fast and responsive — smarter caching that
> tolerates a read-only BQuant filesystem, and event-driven chart controls so
> switching a benchmark re-renders that chart instantly instead of forcing a
> full refresh.

## 1. Summary & non-goals

Three optimization fronts:

1. **Caching** — add an in-memory session cache (the BQuant filesystem may be
   read-only) and speed up the dashboard generally.
2. **Event-driven chart controls** — changing **benchmark** (and future
   **lookback**) dropdowns updates charts immediately, *outside* the filter /
   multi-strategy-selection flow.
3. **Benchmark switches re-render on switch, not on a total refresh.**

**Non-goals (hard constraints):**

- **Refresh prices stays the only path that hits BQL** — one fetch per
  refresh; the live controls never refetch (they reuse already-fetched
  prices).
- **Filters and multi-strategy selection still recompute on Refresh** — only
  benchmark/regime (and future lookback) controls become live.
- **No visual change; no new runtime dependencies** (stdlib `functools` /
  dicts only).

## 2. Motivation (current state, with refs)

| Problem | Where | Why it hurts |
|---|---|---|
| Disk cache can crash on read-only FS | `_cache_write` `bql_client.py` L77–81 — `mkdir` + `to_parquet`, **no try/except** | A read-only BQuant filesystem raises; surfaces as a generic "Load failed". |
| No in-memory reuse | only `universe_prices`/`arp_universe_prices` closures (`layout.py` L779/808/1114); **no `lru_cache`** | Derived computations re-run from scratch every recompute. |
| Benchmark change → full Refresh | benchmark dropdowns + regime controls (L215–266) have **no `.observe`**; read only at `_recompute` (L1046–1111) | Re-fetches and re-renders both panes just to change one chart's benchmark — slow and unintuitive. |
| `prep` rebuilt wholesale | `_recompute` builds an immutable `prep` (L1092–1101) and renders both panes | But `prep` depends on **selected tickers, not the benchmark** — so a benchmark change shouldn't need any of it rebuilt. |

The instant-swap precedent already exists: `_on_pick` (L334–339) swaps
`stack.children` to a pre-built view with no recompute. The benchmark
updaters (`_update_outperformance` L1275–1305, `_update_rolling_ref`
L1702–1742, `_update_heatmap` regime path L945–981) derive their benchmark
series from `universe_prices[benchmark]` + `prep.rets`/`prep.sel_window` —
all available **without a refetch**.

## 3. Workstream A — Caching rework

- **In-memory session price cache** (primary fast path): a module-level dict
  (or a field on `DashboardState`) keyed by `(tuple(sorted(tickers)), start,
  end)` → DataFrame, checked before disk in `fetch_prices`.
- **Best-effort disk** (cross-session bonus): wrap the `_cache_write` mkdir +
  `to_parquet` in try/except; **probe writability once** and cache the
  result; on failure, log once and continue in-memory only. `_cache_read`
  is already tolerant (returns `None` on miss).
- **Outcome:** the app never crashes on a read-only filesystem and still
  uses disk when it's writable.

## 4. Workstream B — Memoized derived computations

A **bounded LRU** (a small capped dict, or `functools.lru_cache` on pure
helpers) for the benchmark-dependent results — `rolling_correlation`,
`rolling_beta`, `regime_corr_matrix`, `excess_cum_return` — keyed by a
**hashable signature** `(selected-ticker tuple, benchmark, direction, tail%,
lookback)`. (DataFrames can't be dict keys; key on the ticker/param
signature, not the frames.) Invalidated whenever `prep` is rebuilt (Refresh
or selection change). Lives in a small `src/cache.py` util or on
`DashboardState`. This makes flipping **back** to a previously-viewed
benchmark instant.

## 5. Workstream C — Event-driven "live" chart controls

- **Store current state for reuse:** keep the current `prep` and
  `universe_window_start` on `DashboardState` (today `prep` is local to
  `_recompute`) so observers can re-render without a refetch.
- **Wire observers:** add `.observe(names="value")` on each per-pane
  benchmark dropdown (`rcorr_benchmark_dd`, `rbeta_benchmark_dd`,
  `outperf_benchmark_dd`) **and all** heatmap regime controls
  (`heat_benchmark_dd`, `heat_dir`, `heat_pct`, plus the regime checkbox's
  data path) → a **per-pane partial-render callback** that recomputes only
  the affected chart from the stored `prep` + `universe_prices[benchmark]`
  and updates that one `FigureWidget` inside `batch_update()`.
- **Reuse, don't duplicate:** factor the benchmark-series-slice logic
  currently inline in `_render_pane` into a helper shared by `_render_pane`
  and the live callbacks; reuse `_update_outperformance` /
  `_update_rolling_ref` / `_update_heatmap` as-is.
- **Guards:** if there's no selection or `prep is None`, no-op (no error, no
  fetch). The regime checkbox keeps its visibility-sync observer; the data
  re-render is added on top.
- **Reusable pattern:** a small `bind_live_control(widget, render_fn)` helper
  so v0.7.0's lookback selectors inherit the same wiring for free.

## 6. Workstream D — General speedups

- On a benchmark/regime change, re-render **one** chart — not both panes, not
  all 9 views.
- Profile `build_app` init; eliminate redundant recomputation (e.g. compute
  `daily_returns` once and thread it; reuse `corr_matrix`); keep the existing
  `batch_update` / `hold_trait_notifications` discipline.
- *Optional stretch:* lazily build off-screen analysis views instead of
  pre-building all 9 at recompute — weighed against the instant picker swap
  (which relies on pre-built views). Noted, not mandated.

## 7. Architecture / state

Centralize on v0.6.0's `DashboardState`: it holds `universe_prices`,
`arp_universe_prices`, the current `prep`, `universe_window_start`, and the
memo cache — the single surface the live callbacks read. This is the clean
home the partial-render path needs.

## 10. Acceptance criteria

- [ ] Changing any per-pane benchmark dropdown or regime control updates **only
  that chart, immediately**, with no "Fetching prices…" pulse and no full
  recompute (mock prices).
- [ ] Flipping back to a previously-viewed benchmark is instant (memo hit).
- [ ] A simulated read-only filesystem does **not** crash the app — it falls back
  to in-memory caching and still renders.
- [ ] **Refresh prices** still performs exactly one BQL/mock fetch + full
  recompute; filters & multi-strategy selection still recompute only on
  Refresh.
- [ ] `ruff`/`black`/`pytest` (from v0.6.0) stay green; `.meta/VERSION` → `0.6.9`
  at release; `CLAUDE.md` convention updated; this file updated with the
  shipped PR list.
