| `src/price_source.py` | `PriceSource` protocol + `BqlPriceSource` / `MockPriceSource` (v0.9.16 #222) — *where prices come from*, extracted from `bql_client` so the choice is a value you pass rather than an inline branch, and the mock's rejection seams are instance attributes rather than module globals tests had to clear. **The shared contract is failure shape, not just output shape:** a wide date×ticker frame in request order; an unresolvable ticker among healthy peers degrades to a NaN column with a warning (#187); a request where *nothing* resolves raises `TickersUnresolved` (#193), which is deliberately distinct from a transport failure because a single added benchmark has no peers to degrade against. **`BqlPriceSource`** owns the batching ladder — `assemble_batches` (one request per `batch_size` chunk), `fetch_batch_with_retry` (exponential backoff, `max_retries`), `salvage_batch` (a failed batch re-fetched one ticker at a time, so a single bad ticker can't blank a one-batch universe) — plus the module-level `_reshape_bql_response` / `_pick_column` / `_chunked` helpers; its `service_factory` is injectable, and deferred to the first fetch so constructing one off-terminal is harmless. **`MockPriceSource`** mirrors that contract with `hash(ticker)`-seeded series (see #235) and carries `unresolvable` / `first_trade` as attributes. `default_price_source()` picks BQL when the library imported, else the mock. |
| `src/price_cache.py`  | `PriceCache` (v0.9.16 #221) — the two-tier price cache, extracted from `bql_client`'s module globals so it is an object with a lifetime rather than a process-wide singleton (two instances are independent; tests construct their own instead of resetting globals). Leaf module, like `cache.py`. **Incremental in-memory superset (v0.9.13, #165):** one growing frame `.superset` + the covered date interval `.cover`, tracked separately from the data index so a weekend/holiday `end` still counts as covered. A request whose tickers ⊆ the superset's columns and whose `[start, end]` ⊆ the cover is served by *slicing* (`covers` / `serve`), no BQL; a miss fetches only the missing rectangle — new tickers and/or the uncovered date extension (`delta_specs`) — and merges it in (`merge`, fresh wins), so a lookback change or an added index costs a delta, not a whole-universe refetch. `use_cache=False` (Refresh) refetches the full request and overwrites the overlap. **Parquet tier:** a same-`end`-day file under `cache_dir` (`data/.cache/prices_{YYYY-MM-DD}.parquet`, TTL `ttl_hours`) via `read_disk` (containment-aware: column-pushdown `read_parquet(columns=…)`, left-date coverage check) / `write_disk` (writes the superset, prunes past-TTL files via `prune`). Writes are best-effort — `.disk_writable` is the tri-state probe that warns once and degrades to in-memory on a read-only FS. `clear()` drops all three. |
| `src/cache.py`        | `LRUCache` — a tiny bounded LRU (`OrderedDict`-backed, stdlib only) with `get_or_compute(key, fn)` / `clear()`. Leaf module (no project imports). Memoizes the benchmark-dependent chart results (v0.6.9 Workstream B); reusable for future live controls. |
| `src/commentary.py`   | The two whole-catalog commentary builders, both computing from the already-fetched prices with no BQL of their own: **`build_leaderboard(meta, prices, returns, *, window_days, rows, history_returns)`** (v0.9.20 #287, rescored v0.9.22 #310) — the ranked board behind the Leaderboard section. Returns one frozen `LeaderboardColumn` per entry in `RANKABLE_METRICS` (the four `(key, label)` pairs in display order, in `config.py` since v0.9.23 #328 so the catalog table's Metric chips read the same set — the two boards rank the same catalog by the same kind of number, and the widget titles its columns from the data it is handed), each holding `top` and `bottom` tuples of frozen `LeaderboardRow`s. Return is `period_return` over `window_days`; Sharpe / Calmar / Sortino are `ann_sharpe` / `calmar_ratio` / `sortino_ratio` at `years = window_days / TRADING_DAYS_PER_YEAR`, so all four columns scope identically. **Ranked by the z-score, descending** (#310): each metric is standardized against its *own* trailing history by `rolling_metric_zscore` over `history_returns` (the unsliced frame the app passes), so "a good Sharpe" means good *for this index* rather than good against a cross-section that mixes asset classes. `score` is that reading and `score_text` its `+0.00` rendering; the widget shows `rank · ticker · score (value)` with the sentiment colour on the score, because that is what the row is ranked by. NaN and infinite values are dropped before ranking and ties break by ticker. `rank` is the index's true catalog position, so a bottom row reads "52 of 54"; `text` is the pre-formatted **raw** value (percent for the return, 2dp for the ratios) because the formatter differs per column. This is a different figure from the **asset-class-demeaned** z-score on the catalog's Z-Score column — that one compares an index to its peers, this one to its own past. The bottom block starts after the top block, so a catalog smaller than `2 * LEADERBOARD_ROWS` yields a short `bottom` rather than a repeated row. **`window_returns(prices, *, window_days)`** derives `daily_returns` over a tail that is a strict superset of every returns-based metric's window (plus one leading row so the oldest return has its true prior), so feeding it to `build_leaderboard` gives a board identical to feeding the full-history returns without the whole-history `pct_change` — pinned by a test, since the optimisation is invisible or it is a bug. (Named `superlative_returns` until v0.9.20 #291.) **`load_commentary_notes(path=COMMENTARY_PATH)`** (v0.9.22 #304) reads `data/commentary.json` into frozen `CommentaryNote`s (`title`, `date`, `text`), **newest first, and never raises**: it runs while the app is being built, so a missing file is silent (a catalog with no commentary yet is an ordinary state), while an unreadable one, malformed JSON or the wrong top-level shape each warn and yield `[]`, and a single bad note is skipped by position rather than voiding the file — one typo in an old note must not take today's note off the screen. `text` is carried **verbatim**; the escaping and the paragraph split are the renderer's (`_render_note_paragraphs`), the way `LaunchCard` leaves its em dash to `_fmt_since_return`. | `src/layout/rails.py` | **Control containers and the chip groups they carry (v0.9.21, #277; v0.9.23 #326).** `control_bar(*RailSection, title=None)` lays its sections **across**, under an optional title naming what they belong to (the catalog's Group by / Metric / Window are three facets of one table view and pass one; the Leaderboard's Window and the Bulletin's board switch stand on their own and pass none). It was a *rail* first — the same headed sections stacked down a fixed-width column beside the catalog table, with the bar added as "the same rail turned on its side" — until #326 removed the last rail and the column builder with it. `.bbg-rail` survives as the surface a bar is drawn on, which is why these names still read as they do; the module docstring carries the history. `ChipGroup` is the value-carrying primitive: a `W.VBox` of `.bbg-pill` chips presenting a **`W.Dropdown`'s surface** — `value`, `label`, `observe(..., names="value")` — so a call site that reads a dropdown needs no rewrite beyond its annotation. That is not cosmetic: `PlatformAnalytics` takes two of these by constructor injection and reads `.value` to compute, **`.label`** to title the z-score column, and `.observe` to re-render (#279), and `.label` is a Dropdown API a bare row of buttons does not have. `MultiChipGroup` is the multi-select flavour and reports **membership**: its `value` is normalized into options order on every write, so a click sequence cannot reach a reader — the catalog nests by the hierarchy and never by tick order (#273), and this makes that structural rather than remembered. ## UI layout

The screen layout is: masthead banner → all-catalog commentary
block (always visible; **an error strip full width on top**, then two sections
side by side at 60:40 — v0.9.22 epic #303) → **top-level pill-button tab bar**
with three tabs → disclaimers.

### The commentary block's two sections

Both are built by **`section_panel(title, bar, body, *, height)`**
(`rails.py`) — a title line in the `grid_header` treatment, the section's
`control_bar` of chips, then a bordered `.bbg-section-box` that scrolls its body
inside a fixed height. It is the Platform tab's arrangement, named so the three
copies cannot drift apart.

- **Left — Leaderboard** (`Leaderboard`), under a **Window** chip group
  (`LEADERBOARD_WINDOW_OPTIONS`: `1W/1M/3M/6M/1Y`). Four columns — Return,
  Sharpe, Calmar, Sortino — each listing the catalog's top `LEADERBOARD_ROWS`
  and bottom `LEADERBOARD_ROWS` as **`rank · ticker · score (value)`**,
  separated by a divider, with the strategy name on hover. Ranks are **true
  catalog positions**, so the bottom block of a 54-index catalog reads
  52/53/54. **Ranking is by the score** (#310) — the metric standardized
  against its own trailing history via `rolling_metric_zscore` — with the raw
  value it was computed from in parentheses behind it, and the sentiment colour
  on the score rather than the value. **Clicking any row opens that strategy in
  Single Strategy**, via the same `_show_in_single_strategy` the catalog grid
  uses. The chips re-rank live from the cache — no BQL. The board carries no
  title of its own: `section_panel` heads the section and the lit chip names
  the window.
- **Right — QIS Bulletin** (`CommentaryPane`): a *Commentary* | *New Launches*
  **chip pair** over one board at a time. Commentary is the default and renders
  the authored notes from `data/commentary.json` (`_render_commentary_notes` →
  `notes_board` + one `commentary_card` per note); the launch board is the
  `launches_board` template. Neither titles itself and neither caps its own
  height — the section title, the lit chip and the box own all three. Switching
  issues no BQL, and new launch cards arriving on a Refresh do **not** yank the
  pane away from whatever is open.

The two columns take `flex: 1 1 COMMENTARY_LEADERBOARD_SHARE` and
`flex: 1 1 COMMENTARY_BULLETIN_SHARE` (60% / 40%) with `min-width: 0` on both,
so the ratio holds as the viewport narrows and the leaderboard's four columns
narrow rather than pushing the Bulletin off the row. The error strip sits
outside both, so neither the window chips nor a board switch can wipe an init
error.

*(This replaced the v0.9.20 arrangement — a self-titling board beside a
pill-pair pane on a `flex: 0 0 620px` basis, with the Commentary board a single
undated `weekly_commentary.html` blob the app stamped with today. That in turn
replaced the v0.8.x Weekly-Commentary-above-Key-Highlights layout, whose left
board was 16 Market Superlative cards, retired in #291.)*

### The three tabs

- **Platform** (v0.9.21, epic #276; completed v0.9.23, epic #321) — **one
  control bar over a full-width grid**. The bar is `control_bar`
  (`src/layout/rails.py`) carrying `ChipGroup` chips; the table stands at a fixed
  `CATALOG_TABLE_HEIGHT` (see `style.md`) and takes the whole panel width. A
  fixed-width ranking rail stood down the table's left side until #324–#326
  emptied and then removed it.
  - **The bar — *Table view*: Group by · Metric · Window**, in the order they
    act in. Which classification levels the table nests by
    (`UNIVERSE_GRID_GROUPABLE_FIELDS`, membership only — the nesting order is
    always the hierarchy's, never the tick order), then which metric the
    ranking column scores, then which single stats window is shown. The window
    does **two** jobs (#324): the performance columns it does not show are
    *hidden, not dropped*, so none of them recomputes — but it is also the
    window the score is measured over, so a change renames the ranking column
    and re-sorts the frame, and the table is rebuilt as a grouping change
    rebuilds it. The selected row does not survive that; the rows moved.
  - **The table** — every index with its metadata plus the stats of the chosen
    window. The Sharpe cells are **conditional-formatted** (diverging
    red→neutral→green); the classification tiers are drawn as **nested
    row-group headers** in stepped cyan bands rather than as repeated body
    columns; the search box leads from the **top-left**, and a **per-column
    filter row** sits directly beneath the header labels (text columns only —
    a substring filter over a number matches nonsense). Clicking a row opens
    that strategy in Single Strategy.
  - **The ranking column** sits right after the Info block and the grid is
    **sorted by it** descending (v0.7.0 Workstream A). Since epic #321 it is
    the bar's Metric — `RANKABLE_METRICS`, the Leaderboard's own
    Return/Sharpe/Calmar/Sortino — over the bar's Window, standardized against
    a fixed `SCORE_SAMPLE_DAYS` of that metric's own rolling history, and
    headed **`Normalized <window> <metric> (5Y Z-Score)`** with the `5Y` built
    from `LOOKBACK_YEARS`. Recomputed live from the already-fetched cache (via
    `rolling_metric_zscore`, no BQL). Two things to know before touching it:
    every consumer is handed **the column's key**, never a parse of its header
    (#323), and a ticker that cannot supply `CATALOG_SCORE_MIN_SAMPLE_DAYS` of
    the sample renders a dash instead of a score. `_window_of` must keep
    returning None for the header, which embeds a window label of its own —
    that is what stops a stats-window change hiding the ranking.
    Below the grid, the analytics card (`.bbg-card`) is **a chart beside its
  own points** (epic #331, v0.9.24). Its controls are a second `control_bar` in
  the table's chrome, titled **Chart view**: **Chart · Metric · Window ·
  Regime · Solution**, with **Scope · Level** on the drill strip below it.
  Metric offers `rankable_metric_chips()` and Window
  `stat_windows()` — the table's own lists, so the two surfaces can be read at
  different windows but cannot *offer* different things. **Solution** (v0.9.27)
  is the universe filter: one solution at a time, offered from the drawn
  universe rather than from `UNIVERSE_SOLUTION_VALUES` (the catalog's `Beta`
  solution does not survive the universe filter, and a chip for it would draw
  an empty chart), repopulated by `_sync_solution_chips` on every render behind
  a `_syncing_solution` guard so its own observer cannot re-enter mid-render.
  Sections the active
  chart does not read are **hidden, not rebuilt** (`layout.display`), so a chip
  keeps its selection across a chart switch: Regime shows only on the Scatter,
  Metric and Window hide on the Strip (its metric and window are fixed), and
  Level hides on the Icicle, which draws every level at once and zooms
  itself.

  The **Icicle** draws `ANALYTICS_LEVELS` → ticker. Every leaf counts **1**
  with `branchvalues="total"`, so a cell's width is its share of *strategies*
  at every level — the sunburst it replaces sized arcs by |z|, the gross
  magnitude of what colour already encoded, so a ring's shares read as nothing.
  Colour is the leaf's **raw** metric averaged up each level, on the diverging
  ramp with a range taken from the data and clipped at the 95th percentile of
  |value| (the fixed ±2 was a z-score's range). A cell's id **is** its path, so
  a click round-trips into a `Drill.scope` and a label under two parents stays
  two cells. Its trace is built from the **pinned solution's** rows only and
  its `level` from the scope, so neither a Plotly zoom-out nor a re-render can
  leave the filter (v0.9.27). `pathbar=dict(visible=False)`: Plotly's ancestor
  bar defaults **on** and draws a grey strip of chrome saying what the Scope
  breadcrumb already says.

  The **Scatter** is the regime view and the factor view merged (they were two
  per-strategy scatters answering halves of one question — one had the filter
  and no factor axes, the other the axes and no filter). **Y = the metric over
  the Window, X = term-premium β, Z = equity-risk-premium β**, all over one
  sample: the Window's days restricted to the regime bucket. The regime
  controls are unchanged in meaning — Type and Bucket are now `ChipGroup`s,
  Source stays a dropdown because its options are a long live list; Volatility
  uses fixed VIX-level buckets (`VIX < 15` / `15 ≤ VIX < 25` / `VIX ≥ 25`)
  while Trend and Rate-level split a live indicator into **low / middle / high
  terciles** via `tercile_bounds` (Trend = the selected benchmark's 21-day
  return autocorrelation, Rate-level = the selected regional risk-free rate).
  The origin is drawn by the **axes** — a `zeroline`, a wall `line` and a
  `gridcolor` per scene axis, with `aspectmode="cube"` — because the
  translucent mesh planes that used to mark it dimmed the markers behind them.

  The **Strip** is `STRIP_DAYS` **weekday** columns of 1D returns — T-1 back to
  T-6, never today, whose return is against a price still moving — one marker
  per point per date, jittered within its column on a **numeric** axis wearing
  the dates as tick labels (a categorical axis puts every marker of a column on
  one line). It is the only view on the card that can draw *this week*.

  All three **drill**, through one frozen `Drill(scope, level)` written by one
  setter (`src/layout/drill.py`). The stops are the hierarchy's own —
  `drill_levels()` is derived from `ANALYTICS_LEVELS` plus the ticker leaf
  (v0.9.25), and since v0.9.27 the first of them, `solution`, is the **base**
  rather than a stop: the Level chips offer `drill_levels()[1:]`, the scope is
  based at `(solution,)`, and the breadcrumb names the solution as its root and
  shows `scope[1:]`. `set_drill` clamps a level the chips do not offer —
  `next_stop(())` still names `solution`, and assigning it raised inside the
  breadcrumb callback, where a raise reads as a dead control; `narrow_to`
  clamps an empty path back to the base. A node is a **path**, never a bare
  label. A group's value is the **equal-weight mean** of its members, taken
  after the regime mask. Colour **keys to the points shown** — their own level
  — because a key that stops varying stops informing.

  The **points table** (`ChartPointsGrid`) sits beside whichever chart is
  active, reading its `points()` and never a figure's traces: `<Level> · Name ·
  <value label>`, plus **Count** only when some row stands for more than one
  strategy, sorted by value descending with blanks last. A row click routes on
  the **`leaf` flag** — a group narrows the drill, a strategy opens in Single
  Strategy through the same `_show_in_single_strategy` the catalog grid and the
  leaderboard use. **Never on `count`:** a one-member group has a count of 1
  too. Chart and table stand at one fixed `ANALYTICS_HEIGHT`, **and the figures
  are built at it** (`ANALYTICS_HEIGHT_PX`, v0.9.27) rather than at the app-wide
  `CHART_HEIGHT` that used to overflow the box.
  Everything recomputes from the fetched cache; **no control here issues BQL**.
- **Multi-Strategy** (epic #341, v0.9.29) — **the catalog table with ticks.**
  Top to bottom: a `section_panel` titled *Strategy selection* with **Refresh
  prices** on its title line; a `control_bar` titled *Table view* reading
  **Group by · Window · Benchmark · Filter**; a `FilterStrip` of the active
  dimension's values under it; the `BasketGrid` at `CATALOG_TABLE_HEIGHT`; the
  **Basket strip** of cards at `BASKET_STRIP_HEIGHT`; the selected-strategy
  perf grid; the two analysis panes.

  What this replaced (v0.8 idiom, retired in #344/#345): a `W.Accordion`
  holding a 38% column with a 240px `CheckboxMultiSelect` of the whole catalog
  beside a 60% column of pill-tabs over more checkbox groups, nine `≥ / ≤`
  threshold rows, a currency dropdown, and two `W.DatePicker`s for the analysis
  range. `CheckboxMultiSelect` is deleted; `FilterPanel` survives as **Single
  Strategy's** accordion and nothing else.

  **`BasketGrid(CatalogTable)`** is the picker: the same frame, grouping,
  search and per-column filter row as the Platform's table, in Select's
  `multi` style with the tick drawn into the first visible column, *Select all
  shown* / *Select none* in the `layout`'s `topStart`, and row-group headers
  wired as hit areas. `_on_selected_rows` reconciles **by ticker, never by
  position** — removes before adds, so a swap at the cap works; a rejected add
  re-pushes the previous positions and calls `on_limit`; a member outside the
  frame is untouched. `_set_data` clears `selected_rows` *before* the write and
  re-pushes after, because itables validates them against the incoming frame
  and raises on a narrowing filter.

  **`Basket`** (`src/layout/basket.py`) is the only selection state: an ordered
  ticker tuple plus the cap, with `add` / `remove` / `toggle` / `replace` /
  `clear` all checking the cap **before** assigning, and a `value` validator as
  the floor under them. `BasketCards` draws one `.bbg-basket-card` per member —
  asset-class tag from `group_colors`, a mono ticker button into Single
  Strategy, a muted name, an **×**, and a marker on the window's binding member
  — and `WindowReadout` renders the `BasketWindow`.

  **The window is `basket_window(sel_5y)`**: the intersection of the members'
  histories inside the five-year lookback, plus the member binding each edge.
  Nothing on the tab can move it.

  **`_schedule_reslice`** re-renders the perf grid and both panes on a
  `RESLICE_DEBOUNCE_S` timer after any basket write, with **no BQL** — deferred
  by re-arming while `refresh_inflight` is set, and synchronous when there is
  no frontend so a test sees the render immediately.

  **`FilterStrip`** (`src/layout/filter_strip.py`) owns one `MultiChipGroup`
  per dimension plus the Launch-date pickers, all built once and swapped by
  `display`; `apply` runs the same `apply_filters` reducer `FilterPanel` runs.
  **`QuantColumns`** (`src/layout/quant_columns.py`) is the memoised metric
  table both tabs read, keyed on `(years, benchmark)` and on the **identity**
  of the price frame, so a refetch cannot serve stale numbers.


- **Single Strategy** (v0.9.0) — a per-strategy deep-dive. A two-column
  **"Filters" accordion** (v0.9.12, `make_filter_panel`): the **left column** is
  the **single-select strategy picker** with a **shared benchmark selector** +
  **"Show benchmark" toggle** stacked below it; the **right column** is the
  filter criteria (the same schema-derived pill bar / checkbox groups /
  Characteristics / Quantitative views as the Multi-Strategy tab), stretched
  to equal height. The
  criteria **narrow the picker live**: unlike Multi-Strategy there is **no
  Refresh-prices button** — toggling any filter box re-renders the tab
  immediately off the cache, and when the picked strategy is filtered out the
  first still-matching strategy is auto-selected. (The picker + benchmark drive
  every section; benchmarks ride the single startup fetch, no BQL.) Three
  stacked sections:
  1. **Profile + cumulative chart** — a two-column row: a metadata **profile
     card** on the left (`_render_profile_card`, including the v0.9.0
     `description`, NA-safe when missing) and, on the right, a cumulative
     performance chart (with the optional benchmark overlay) above a compact
     standard-perf table.
  2. **Monthly-return calendar** — a **3-pill** table (**Absolute** /
     **Outperformance** / **Vol-adjusted**) rendered over one DataGrid via
     `calendar_return_table`; the pills swap which year×month matrix shows.
  3. **Two analysis panes** — a two-pane section mirroring the Multi-Strategy
     tab: two side-by-side panes, each with its own analysis picker and a

     picked strategy (weekly-returns β scatter, strategy-vs-benchmark return
     distribution, monthly factor-correlation scatter, drawdown, factor

  Every view computes from the cached `state.universe_prices` (no extra BQL
  call) and reuses the existing panes / grids / charts / filters / html
  helpers (see `src/layout/single_strategy.py`).

Below the tab content: performance disclaimer (templated with the data
window) → bottom legal disclosure (justified).
