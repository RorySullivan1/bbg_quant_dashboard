# Architecture & UI layout

Part of the `bbg_quant_dashboard` repo memory — split out of `CLAUDE.md`.

## Architecture map

| Module                | Owns                                                                   |
| --------------------- | ---------------------------------------------------------------------- |
| `src/config.py`       | Constants: lookback, new-launch window, Sharpe windows, file paths, `UNIVERSE_SOLUTION_VALUES` (in-universe solutions), `REGIME_SPECS`/`REGIME_TICKERS`/`LEVEL_INDICATOR_MOCK`, benchmark/factor tickers. **Home of the catalog schema (v0.9.15, #208):** `CatalogField` + `CATALOG_SCHEMA` declare every metadata column once — internal key, accepted JSON aliases, display label, role (`tier`/`attribute`/`date`/`text`) — with `CLASSIFICATION_TIERS` ordering the tiers top→leaf. The per-renderer field tuples (`CATALOG_GRID_FIELDS`, `PERF_GRID_FIELDS`, `PROFILE_CARD_FIELDS`, `LAUNCH_CARD_META_FIELDS`), `SUNBURST_LEVELS`, and the accessors (`catalog_field`, `field_label`, `tier_fields`, `filterable_fields`, `filter_dimensions`, `sunburst_levels`) live here too, so **labels and column order are configuration, not code**. The accessors read `CATALOG_SCHEMA` at call time, not through an import-time lookup, so a swapped schema reaches every consumer. See `data.md`. |
| `src/style.py`        | Centralized style tokens: `Color`, `Font`, `FontSize`, `StatusTone`, `Sentiment` enums plus `LINE_PALETTE`. `Color` carries the dark-chrome group (`CHROME_BG`, `SURFACE`, `SURFACE_2`, `BORDER`, `TEXT`, `TEXT_MUTED`, `ACCENT`, `ACCENT_2`, `SCRIM`) and `FontSize.TITLE` (masthead). All inline CSS / `data/templates/` reference these — change hex/font values here, not at call sites. (v0.6.5 moved tab/filter-pill state to the `.bbg-pill.is-active` CSS class, so the old `TabButtonTone` enum was retired.) |
| `src/data.py`         | Loads JSON metadata, filters it, lists unique values for dropdowns. **Schema-driven since v0.9.15 (#209):** it knows no column name of its own — `load_metadata` resolves each `CATALOG_SCHEMA` field against the first of its `sources` aliases present (a legacy alias or an unknown feed key warns rather than raising) and derives `META_COLUMNS` from the schema; `apply_filters(df, filters, *, live_date_min, live_date_max)` is keyed by internal field name, so adding or renaming a dimension is a schema edit, not a signature change. |
| `src/bql_client.py`   | `fetch_prices(tickers, start, end, use_cache=True, cache=None, source=None) -> (df, source_name)` — the one entry point the app uses, now just the orchestration between a `PriceSource` and a `PriceCache` (v0.9.16 #222 split the fetching out, #221 the caching). Serves a contained request by slicing the cache, else fetches only the missing rectangle through the source and merges it in; `use_cache=False` (Refresh) refetches the full request. Both collaborators default to a module-level instance (`_DEFAULT_CACHE` / `_DEFAULT_SOURCE`), so callers pass nothing and a test passes its own. Re-exports `TickersUnresolved` / `HAS_BQL` so existing imports are unchanged. `default_window(lookback_years)` lives here too. |
| `src/stats/`          | Metrics **package** (was a single `stats.py`; split in v0.6.0 G stretch into `_common` / `performance` / `risk` / `rolling` — plus `factors` (v0.7.0), `regime` (v0.8.5), and `calendar` (v0.9.0) — with a flat re-exporting `__init__.py`, so `from src.stats import X` / `stats.X` is unchanged). Per submodule:<br>• **`_common`** — price/return primitives: `daily_returns`, `drawdown_series`, `max_drawdown`, `max_drawup`, `zscore_cross_section` (cross-sectional z of a per-ticker metric), `asset_class_demeaned_zscore` (cross-asset-neutral ranking), `common_window_bounds` (overlap window across columns — max first-valid / min last-valid date — drives the Multi-Strategy date-range box bounds), `active_columns` (columns that moved over the trailing ~21 trading days — drives the v0.8.9 stale-index prune).<br>• **`performance`** — `cum_perf`, `total_return`, `weekly_change`, `period_return`, `longest_up_streak` / `longest_down_streak`, `ma_spread`, `trend_strength`, `return_autocorr`, `macd_histogram`, `win_rate`, `excess_cum_return` (cumulative excess return vs a benchmark, pp), `ann_return`, `ann_volatility`, `ann_sharpe`, `perf_table`, `since_inception_perf` (pure util; **unwired from the grid in v0.7.2** but kept + tested), `universe_perf` (1Y / 3Y / 5Y windows only — Since-Inception dropped in v0.7.2).<br>• **`risk`** — `corr_matrix`, `regime_corr_matrix` (correlation over a benchmark-return tail, benchmark added to the matrix), `heatmap_corr_matrix` (backs the Correlation Heatmap pane), `return_distribution_stats`, `return_skew`, `recovery_days`, `ann_beta` (scalar beta vs a benchmark over a window — v0.9.13 #167 vectorized the per-column pairwise cov, no `.apply` loop), `calmar_ratio`, `treynor_ratio`, `jensen_alpha` (vs a benchmark, rf=0), `downside_deviation`, `sortino_ratio`, `historical_var` (positive daily VaR loss), `rsi` (Wilder RSI), `quant_metrics_table` (per-ticker Sharpe/Sortino/Calmar/Beta/Treynor/Jensen/VaR/RSI table for the Quantitative filter).<br>• **`rolling`** — `rolling_return`, `rolling_volatility`, `rolling_sharpe`, `rolling_sortino`, `rolling_metric_zscore` (generalizes `sharpe_zscore` over metric/window/lookback), `sharpe_zscore` (scalar, whole-catalog highlights), `rolling_sharpe_zscore` (time series, selected-set chart), `rolling_correlation`, `rolling_beta`.<br>• **`factors`** (v0.7.0) — `equity_risk_premium` / `term_premium` (daily factor-return proxies from the fetched factor tickers, return spreads since BQL is `px_last`-only), `trend_returns` (v0.7.1: daily returns of the `TREND_TICKER` — the trend β is taken vs the index's own returns, not a spread), `factor_beta` (thin `ann_beta` wrapper vs a factor-return series), `platform_sunburst_frame` (per-ticker grouping columns — one per `config.SUNBURST_LEVELS`, default `asset_class` + `category` (v0.9.15 #213) — plus a single `z` over a selectable metric/window/lookback — default z(1W Sharpe, 1Y); v0.8.x sunburst, replacing the two-metric `platform_treemap_frame`).<br>• **`regime`** (v0.8.5) — `regime_mask` (half-open `[low, high)` indicator-bucket membership, NaN-safe, ±inf open ends), `regime_risk_return` (per-ticker vol/ret/sharpe over the masked days, *mean-based* annualization since regime days are non-contiguous), `rolling_autocorr` (rolling lag-1 return autocorrelation series — drives the Trend regime), `tercile_bounds` (the `(low, high)` of an indicator's low/middle/high third by its 1/3 & 2/3 quantiles — drives the Trend / Rate-level terciles; degenerate → all-days). (v0.8.7 dropped `regime_correlation` with the Platform Correlation sub-tab.)<br>• **`calendar`** (v0.9.0) — `monthly_returns`, `weekly_returns`, `monthly_realized_vol` (resampling helpers), `calendar_return_table` (a year×month absolute / outperformance / vol-adjusted return matrix) + `calendar_summary_columns`, `monthly_factor_correlations`, plus the regression helpers `monthly_beta`, `monthly_correlation`, `ols_fit` / `OLSFit`, `poly_fit` / `PolyFit` — they back the Single Strategy tab's calendar (Section 2) and its factor/analysis panes (Section 3), computed from the cached prices, no BQL. |
| `src/price_source.py` | `PriceSource` protocol + `BqlPriceSource` / `MockPriceSource` (v0.9.16 #222) — *where prices come from*, extracted from `bql_client` so the choice is a value you pass rather than an inline branch, and the mock's rejection seams are instance attributes rather than module globals tests had to clear. **The shared contract is failure shape, not just output shape:** a wide date×ticker frame in request order; an unresolvable ticker among healthy peers degrades to a NaN column with a warning (#187); a request where *nothing* resolves raises `TickersUnresolved` (#193), which is deliberately distinct from a transport failure because a single added benchmark has no peers to degrade against. **`BqlPriceSource`** owns the batching ladder — `assemble_batches` (one request per `batch_size` chunk), `fetch_batch_with_retry` (exponential backoff, `max_retries`), `salvage_batch` (a failed batch re-fetched one ticker at a time, so a single bad ticker can't blank a one-batch universe) — plus the module-level `_reshape_bql_response` / `_pick_column` / `_chunked` helpers; its `service_factory` is injectable, and deferred to the first fetch so constructing one off-terminal is harmless. **`MockPriceSource`** mirrors that contract with `hash(ticker)`-seeded series (see #235) and carries `unresolvable` / `first_trade` as attributes. `default_price_source()` picks BQL when the library imported, else the mock. |
| `src/price_cache.py`  | `PriceCache` (v0.9.16 #221) — the two-tier price cache, extracted from `bql_client`'s module globals so it is an object with a lifetime rather than a process-wide singleton (two instances are independent; tests construct their own instead of resetting globals). Leaf module, like `cache.py`. **Incremental in-memory superset (v0.9.13, #165):** one growing frame `.superset` + the covered date interval `.cover`, tracked separately from the data index so a weekend/holiday `end` still counts as covered. A request whose tickers ⊆ the superset's columns and whose `[start, end]` ⊆ the cover is served by *slicing* (`covers` / `serve`), no BQL; a miss fetches only the missing rectangle — new tickers and/or the uncovered date extension (`delta_specs`) — and merges it in (`merge`, fresh wins), so a lookback change or an added index costs a delta, not a whole-universe refetch. `use_cache=False` (Refresh) refetches the full request and overwrites the overlap. **Parquet tier:** a same-`end`-day file under `cache_dir` (`data/.cache/prices_{YYYY-MM-DD}.parquet`, TTL `ttl_hours`) via `read_disk` (containment-aware: column-pushdown `read_parquet(columns=…)`, left-date coverage check) / `write_disk` (writes the superset, prunes past-TTL files via `prune`). Writes are best-effort — `.disk_writable` is the tri-state probe that warns once and degrades to in-memory on a read-only FS. `clear()` drops all three. |
| `src/cache.py`        | `LRUCache` — a tiny bounded LRU (`OrderedDict`-backed, stdlib only) with `get_or_compute(key, fn)` / `clear()`. Leaf module (no project imports). Memoizes the benchmark-dependent chart results (v0.6.9 Workstream B); reusable for future live controls. |
| `src/commentary.py`   | The two whole-catalog commentary builders, both computing from the already-fetched prices with no BQL of their own: **`build_leaderboard(meta, prices, returns, *, window_days, rows)`** (v0.9.20 #287) — the ranked board behind the commentary block's left pane. Returns one frozen `LeaderboardColumn` per entry in `LEADERBOARD_METRICS` (the four `(key, label)` pairs in display order, declared once so the widget titles its columns from the data), each holding `top` and `bottom` tuples of frozen `LeaderboardRow`s. Return is `period_return` over `window_days`; Sharpe / Calmar / Sortino are `ann_sharpe` / `calmar_ratio` / `sortino_ratio` at `years = window_days / TRADING_DAYS_PER_YEAR`, so all four columns scope identically. **Ranked by the raw metric, descending** — the number the row displays — so rank 1 always carries the largest figure; NaN and infinite values are dropped before ranking and ties break by ticker. `rank` is the index's true catalog position, so a bottom row reads "52 of 54"; `text` is the pre-formatted value (percent for the return, 2dp for the ratios) because the formatter differs per column. The bottom block starts after the top block, so a catalog smaller than `2 * LEADERBOARD_ROWS` yields a short `bottom` rather than a repeated row. **`window_returns(prices, *, window_days)`** derives `daily_returns` over a tail that is a strict superset of every returns-based metric's window (plus one leading row so the oldest return has its true prior), so feeding it to `build_leaderboard` gives a board identical to feeding the full-history returns without the whole-history `pct_change` — pinned by a test, since the optimisation is invisible or it is a bug. (Named `superlative_returns` until v0.9.20 #291.) And **`build_launch_cards`** — newest-first new-launch cards (the `LAUNCH_CARD_META_FIELDS` meta line, today `asset_class · category · currency`, launch date, days-since-launch, simple since-launch return). **Retired in v0.9.20 #291:** `build_superlatives` / `SuperlativeCard` / `_SuperlativeBoard`, the v0.8.x 16-card Market Superlatives board the leaderboard replaced. Every metric it used (`return_autocorr`, `longest_up_streak`, `macd_histogram`, `max_drawup`, `win_rate`, `return_skew`, …) still lives in `src/stats/` with its own unit tests — only the card builder went. |

| `src/layout/rails.py` | **Control containers and the chip groups they carry (v0.9.21, #277).** `control_bar(*RailSection, title=None)` lays its sections **across** — for the controls above the table, where a stacked rail would cost vertical space the table wants — and `control_rail(*RailSection, title=None, width=RAIL_WIDTH)` builds a rail — a fixed-basis stack of headed sections, optionally under a rail title (the Z-Score rail's three sections are facets of one control; #278's Group by / Window stand on their own and pass none). `ChipGroup` is the value-carrying primitive: a `W.VBox` of `.bbg-pill` chips presenting a **`W.Dropdown`'s surface** — `value`, `label`, `observe(..., names="value")` — so a call site that reads a dropdown needs no rewrite beyond its annotation. | `src/layout/benchmarks.py` | `BenchmarkRegistry` — the live benchmark ticker list and the selectors bound to it (#190). Every benchmark selector used to be built with `options=BENCHMARK_TICKERS` captured at construction, so the list was frozen once `build_app` returned. Selectors now `register()` with the registry instead: `add()` appends (deduped, order-preserving) and broadcasts to all of them, **preserving each selector's current value** when it survives. `build_app` creates the registry before any widget and threads it into `_make_benchmark_dropdown` / `_make_analysis_pane` / `_make_single_analysis_pane` / `make_filter_panel` / `make_single_strategy_panel`, then stores it on `DashboardState.benchmarks`; the `registry=None` default leaves standalone callers on the curated snapshot. **Persistence + removal (#194):** `src/user_benchmarks.py` stores the user's additions — **not** the curated list, which ships in `config.py` — as `data/user_benchmarks.json` (`USER_BENCHMARKS_PATH`, gitignored). A sibling of the catalog rather than a file under `data/.cache/`, because the cache is semantically deletable and user configuration is not. Both operations are best-effort on the same tri-state contract as the parquet cache: `load_user_benchmarks()` runs during `build_app` before anything is on screen, so a missing / empty / malformed / wrong-shaped / unreadable file all return `[]` rather than taking the app down; `save_user_benchmarks()` warns once, sets the store's `writable=False`, and returns False rather than failing the add. Both are thin wrappers over a module-default `UserBenchmarkStore` (v0.9.16 #221), which carries the path and the probe — a test swaps in a store pointed at a tmp dir rather than monkeypatching a constant and resetting a global. `build_app` re-adds persisted tickers *after* constructing the registry (a constructor seed would make them curated and unremovable), before `set_persister` (so loading doesn't re-save) and before the first `_fetch_tickers()` (so they ride the startup fetch). The registry gained `_curated` (frozen at construction), `added`, `is_user_added`, `remove` and `set_persister`: only additions persist, only additions can be removed, and `set_catalog` deliberately does not trigger a save. `BenchmarkSelect` shows a `×` button **only while its current value is user-added** (`set_remove_handler`), so a curated benchmark carries no extra UI; removing retargets any selector sitting on that ticker to the first remaining option rather than leaving it holding a value that is no longer an option. Tests are protected by a suite-wide autouse fixture in `conftest.py` that redirects the sidecar path — without it a test run writes a real file into the working tree. **Delta fetch + feedback (#193):** `set_resolver()` installs the callable that decides whether an unknown ticker is usable, and `request(ticker)` is what a selector's commit hook calls — a curated/added/catalog ticker is accepted with no round trip, anything else goes to the resolver and is `add()`ed only once it confirms. `build_app._resolve_new_benchmark` is that resolver: it issues a **single-ticker** `fetch_prices`, which #176's containment cache turns into a delta (only the missing rectangle), then splices the column into `state.universe_prices`. `build_app._fetch_tickers()` is now a *function* rather than a captured list, so added benchmarks ride the Refresh and any lookback change instead of silently dropping out; it reads `meta_all` (not the pruned `meta`) so a resumed ticker can return. **Telling the failure modes apart:** an unresolvable ticker and one with no history in the window both arrive as an empty column. ## UI layout

The screen layout is: masthead banner → all-catalog commentary
block (always visible; **an error strip full width on top**, then two panes side
by side — v0.9.20 epic #286) → **top-level pill-button tab bar**
with three tabs → disclaimers.

### The commentary block's two panes

- **Left — the leaderboard** (`Leaderboard`), under a **Ranking window**
  `1W/1M/3M/6M` toggle. Four columns — Return, Sharpe, Calmar, Sortino — each
  listing the catalog's top `LEADERBOARD_ROWS` and bottom `LEADERBOARD_ROWS` as
  `rank · ticker · value`, separated by a divider, with the strategy name on
  hover. Ranks are **true catalog positions**, so the bottom block of a 54-index
  catalog reads 52/53/54. Ranking is by the **raw** metric, so a row's position
  and the number it shows agree. **Clicking any row opens that strategy in
  Single Strategy**, via the same `_show_in_single_strategy` the catalog grid
  uses. The toggle re-ranks live from the cache — no BQL.
- **Right — the switchable pane** (`CommentaryPane`): a *Commentary* |
  *New Launches* pill pair over one board at a time. Weekly Commentary is the
  default; the launch board is the `launches_board` template. Switching issues
  no BQL, and new launch cards arriving on a Refresh do **not** yank the pane
  away from whatever is open.

The leaderboard takes a fixed flex basis wide enough for its four columns and
the pane absorbs the remainder (`flex: 1 1 0%`), so the split holds at any
viewport width. The error strip sits outside both, so neither the window toggle
nor a pane switch can wipe an init error.

*(This replaced the v0.8.x Weekly-Commentary-above-a-two-section-Key-Highlights
arrangement, whose left board was 16 Market Superlative cards. Retired in #291.)*

### The three tabs

- **Platform** (v0.9.21, epic #276) — a **control bar over the grid and a
  ranking rail down its left**. Both are `ChipGroup` chips in the same chrome
  (`src/layout/rails.py`): `control_bar` lays its sections across, `control_rail`
  stacks them at a fixed 210px basis. The rail is stretched to the table's
  height and capped at the table's own scroll height
  (`CATALOG_TABLE_MAX_HEIGHT`) so the two stand level; the table takes the
  width the rail leaves.
  - **The bar — *Table view*: Group by + Window.** Which classification levels the table
    nests by (`UNIVERSE_GRID_GROUPABLE_FIELDS`, membership only — the nesting
    order is always the hierarchy's, never the tick order) above which single
    stats window is shown. A window change is a **column-visibility** change,
    so the grouping and the selected row survive it.
  - **The table** — every index with its metadata plus the stats of the chosen
    window. The Sharpe cells are **conditional-formatted** (diverging
    red→neutral→green); the classification tiers are drawn as **nested
    row-group headers** in stepped cyan bands rather than as repeated body
    columns; the search box leads from the **top-left**, and a **per-column
    filter row** sits directly beneath the header labels (text columns only —
    a substring filter over a number matches nonsense). Clicking a row opens
    that strategy in Single Strategy.
  - **The left rail — Z-Score ranking.** Metric (Sharpe/Sortino/Return/Vol) ·
    Window (1M/3M/6M) · Lookback (1Y/3Y/5Y), default *z(1M Sharpe, 1Y)*. The
    **dynamic z-score column** sits right after the Info block, recomputed live
    from the already-fetched cache (via `rolling_metric_zscore`, no BQL), and
    the grid is **sorted by it** descending (v0.7.0 Workstream A). Its own
    window is embedded in the column label, which is why a stats-window change
    cannot hide it. Below the grid, the three analytics charts
  live in one **boxed "Platform analytics" card** (`.bbg-card`, v0.8.8) as
  **inner pill-tabs** the user cycles through — ordered **Sunburst → Regime
  analysis → Factor exposures**. A **left-hand control column** (beside the
  flex-grow chart) holds the **shared 6M / 1Y / 3Y / 5Y lookback** `ToggleButtons`
  **stacked on top** (driving all three tabs), with each tab's own extra
  selection boxes swapped in **below** it (v0.8.8; Factor exposures has none, so
  its column is just the lookback). The **Factor exposures** tab is a **3D factor-beta scatter**:
  per-strategy β to the equity risk premium (x) vs β to the term premium (y) vs
  β to the cross-asset trend factor (z, "Trend Exposure"), colored + legended by
  asset class, over three **translucent zero-reference planes** (x=0/y=0/z=0)
  that mark the origin in every dimension (v0.8.6) — computed live from the
  fetched cache, no BQL (v0.7.0 Workstream C+D; promoted to 3D + de-titled in
  v0.7.1). The **Regime analysis** tab (v0.8.5; reworked v0.8.7) is a
  single **regime-conditioned risk/return scatter** (2D per-strategy annualized
  vol-vs-return, colored by asset class) — the Correlation heatmap was removed
  (correlation stays in the Multi-Strategy tab). Controls are a **regime-type**
  dropdown (Volatility / Trend / Rate-level; v0.8.9 dropped the Risk regime), a
  **conditional indicator-source** dropdown (benchmark for Trend / region for
  Rate-level; hidden otherwise), and a **bucket** dropdown. **Volatility** uses
  fixed VIX-level buckets (`VIX < 15` / `15 ≤ VIX < 25` / `VIX ≥ 25`); **Trend**
  and **Rate-level** split a live-computed indicator into
  **low / middle / high terciles** (1/3 & 2/3 quantiles over the lookback
  window, via `tercile_bounds`): Trend = the selected benchmark's 21-day return
  autocorrelation (`rolling_autocorr`), Rate-level = the selected regional
  risk-free rate level (`FEDL01` / `EONIA` / `MUTKCALM`). The scatter conditions on only the days in
  the selected bucket via `regime_mask` / `regime_risk_return`, computed live
  from the cache — all indicators ride the single startup fetch via
  `REGIME_TICKERS`, no BQL. The **Sunburst** tab is a nested **`SUNBURST_LEVELS` → ticker** (today asset class → category)
  sunburst (inside out), driven by a left-column **Metric**
  (Sharpe/Sortino/Return/Vol) + **Window** (1W/1M/3M/6M) Z-score pair plus the
  shared lookback; default **z(1W Sharpe, 1Y)** (v0.8.x, replacing the v0.7–v0.8
  treemap). Each ring's arc is **sized by its
  gross-|z| share** of its parent at every ring (leaf arc = |z|,
  `branchvalues="total"`, so a node's value is exactly Σ its children) and **colored by
  the metric z, averaged up each level** (parent color = mean of its descendant
  tickers' z) on a diverging colorscale + colorbar; the colorbar + hover re-title
  to the chosen metric/window, and the hover shows the arc's % of parent.
  `maxdepth=len(SUNBURST_LEVELS)` shows only the grouping rings up front — the
  ticker ring appears when the user clicks into one (client-side drill-down). All three tabs **re-render live on the shared lookback toggle**
  (the sunburst now shares it too — v0.8.8 dropped its own lookback dropdown);
  the sunburst additionally re-renders on its Metric/Window controls and the
  regime tab on its Type/Source/Bucket dropdowns — all no BQL. Switching tabs is
  a free `.children` swap (the off-tab figures still update in place).
- **Multi-Strategy** — the whole filter UI lives inside an
  expandable **"Filters"** accordion (expanded by default): a full-width
  filter box split into two side-by-side panels — a **left** strategies
  picker (search box above the `ticker_w` dropdown, which stretches via
  `flex` to match the filter panel's height) and a **right** filter
  panel. The right panel
  has an action row on top — **Refresh prices** (green, via the
  `Color.GREEN_600` token, so the primary action stands out) plus **Clear
  section** (clears the active filter pill's selections, or the date
  range/currency on Characteristics, or the ratio thresholds on
  Quantitative) and **Clear all** (clears every filter checkbox group,
  the launch-date range, the currency, the quant thresholds, and the
  search box; selected tickers are kept) — then a pill header bar (same
  `.bbg-pill` style as the top tabs) whose buttons — one per schema
  filter dimension (today Solution / Category / Family / Asset Class /
  Return Type), then **Characteristics** / **Quantitative** — swap which
  dimension's value list shows below. The schema-derived ones show
  checkbox value lists; **Characteristics** shows the
  Launch-date range (two date boxes separated by a hyphen) plus a
  **Currency** dropdown; **Quantitative** filters the universe by
  price-derived ratios — a global Period (1Y/3Y/5Y) dropdown, then one row
  per metric (Sharpe / Sortino / Calmar / Beta / Treynor / Jensen α /
  VaR % / RSI / Z-Score) of
  `[≥ or ≤ dropdown] [value box]`, with an inline parameter dropdown where
  relevant (Beta / Treynor / Jensen each carry their own benchmark
  dropdown, Z-Score its selectable base metric **plus a window dropdown**
  (1W/1M/3M/6M, default 1M; v0.8.11) that sets the lookback the base metric
  is computed over before the cross-sectional z, independent of the Period) — all via
  `quant_metrics_table` / `zscore_cross_section`,
  computed live from the already-fetched prices, no BQL. Below the two
  panels, still inside the Filters accordion, a full-width **"Analysis
  date range"** row holds two hyphen-separated `DatePicker` boxes (the
  `SelectionRangeSlider` was dropped in v0.7.5, leaving just the two boxes,
  min ≤ max linked). Its bounds fit the
  **overlap window of the selected strategies** — `bound_start = max(each
  ticker's first-valid date)`, `bound_end = min(each ticker's last-valid
  date)` via `common_window_bounds` — and the selected sub-range scopes
  the whole selected set (perf grid **and** all pane charts/benchmarks) on
  the next Refresh prices. Below the filter
  box: an
  always-visible selected-strategy performance grid
  (1Y/3Y/5Y per-ticker Return/Vol/Sharpe/Max DD), followed by **two
  side-by-side analysis panes**. Each pane carries its own dropdown
  picker that swaps in any of the 9 analysis types (`Cumulative
  Performance`, `Outperformance`, `1Y Sharpe-z Line`,
  `Correlation Heatmap`, `Risk / Return`, `Drawdown`,
  `Rolling Correlation`, `Return Distribution`, `Rolling Beta`), so
  users can compare any two analyses side-by-side. `Outperformance`,
  Rolling Correlation, and Rolling Beta each carry their own per-pane
  benchmark dropdown that sits on the same row as the analysis picker
  and only appears when the picker is on the relevant analysis.
  (`Outperformance` is the cumulative excess return — strategy minus
  benchmark cumulative % return, in percentage points off a zero
  baseline.) `Correlation Heatmap` additionally carries a per-pane
  **Benchmark** checkbox on that row; ticking it reveals a benchmark
  dropdown and **adds the benchmark as a row/column** to the full-sample matrix
  (v0.8.9), plus a nested **Regime** checkbox; ticking **Regime** reveals a
  **`>` / `<`** tail-direction dropdown (`<` = worst / below-pct tail,
  `>` = best) beside a 0–100% (step 5) tail size, and **additionally** conditions
  the matrix on that benchmark-return regime (the benchmark stays in the matrix)
  (see `regime_corr_matrix`; v0.7.5 restructured these controls, v0.8.9 added the
  benchmark on the Benchmark check).
  Every chart inside a pane renders at the same
  `CHART_HEIGHT` (520px) so the two panes always line up.
- **Single Strategy** (v0.9.0) — a per-strategy deep-dive. A two-column
  **"Filters" accordion** (v0.9.12, `make_filter_panel`): the **left column** is
  the **single-select strategy picker** with a **shared benchmark selector** +
  **"Show benchmark" toggle** stacked below it; the **right column** is the
  filter criteria (the same schema-derived pill bar / checkbox groups /
  Characteristics / Quantitative views as the Multi-Strategy tab), stretched
  to equal height. The
  criteria **narrow the picker live**: unlike Multi-Strategy there is **no
  Refresh-prices button** — toggling any filter box re-renders the tab
  immediately off the cache, and when the picked strategy is filtered out the
  first still-matching strategy is auto-selected. (The picker + benchmark drive
  every section; benchmarks ride the single startup fetch, no BQL.) Three
  stacked sections:
  1. **Profile + cumulative chart** — a two-column row: a metadata **profile
     card** on the left (`_render_profile_card`, including the v0.9.0
     `description`, NA-safe when missing) and, on the right, a cumulative
     performance chart (with the optional benchmark overlay) above a compact
     standard-perf table.
  2. **Monthly-return calendar** — a **3-pill** table (**Absolute** /
     **Outperformance** / **Vol-adjusted**) rendered over one DataGrid via
     `calendar_return_table`; the pills swap which year×month matrix shows.
  3. **Two analysis panes** — a two-pane section mirroring the Multi-Strategy
     tab: two side-by-side panes, each with its own analysis picker and a
     per-pane benchmark dropdown, so the user can compare two views of the
     picked strategy (weekly-returns β scatter, strategy-vs-benchmark return
     distribution, monthly factor-correlation scatter, drawdown, factor
     scoring, plus ranking / PCA / defensive-scoring stubs).

  Every view computes from the cached `state.universe_prices` (no extra BQL
  call) and reuses the existing panes / grids / charts / filters / html
  helpers (see `src/layout/single_strategy.py`).
